# 구현 허브 화면 형식

사용자에게 보여 주는 화면. ID 보다 내용을 먼저 쓴다. 로그·지시서 전문은 붙이지 않고 경로만 쓴다.

---

## 구현 시작 화면

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
구현 시작: {프로젝트명}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
설계 승인: {승인자}, {날짜}
작업 {t}개 (Wave {v}개) · 시험 시나리오 {c}개 (자동 {a} / 사람이 확인 {m})
코드 위치: app/
명령: 설치 `{install}` · 테스트 `{test}` (화면 시험: `{test:e2e}` — {브라우저}, headless, 실제 서버)
진행 방식: Task 마다 개발자 에이전트가 코드와 테스트를 쓰고, 스크립트가 명령을 실행해 통과해야 완료로 기록합니다.
          Wave 가 끝날 때마다 요약을 보여 드리고 커밋 여부를 묻습니다.
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 환경 화면

```
시험 환경 확인 (docs/_gate/build/doctor-*.log)
  cli      있음   (시나리오 {n}개)  ← `node --version`
  browser  없음   (시나리오 {n}개)  ← `npx playwright --version`
없는 환경의 시나리오는 시험 단계에서 '실행 불가'가 됩니다. 인수 전에 설치하거나 사유와 함께 면제해야 합니다.
```

## Wave 요약 화면

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Wave {n} 완료 ({완료}/{전체} Task)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- T-001 {작업} — 통과
- T-002 {작업} — 통과 (설계와 다른 점: {한 줄})
설계와 다른 점 누계 {k}건 · 미해결 보고 {r}건
다음: Wave {n+1} — {Task 수}개
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 검증 충돌 화면 (`conflict`)

```
{T-NNN} 검증이 코드 실패가 아닌 이유로 끝났습니다
  원인: {환경 충돌 — 포트 {n} 사용 중 / 검증 중 앱 파일 변경}
  확인할 것: {남은 서버(띄운 역할이 기록한 PID) / 개발 중인 작업}
  실패 횟수에는 넣지 않았습니다.
```

## 반복 실패 화면

```
{T-NNN} {작업}: 검증이 {k}번 실패했습니다
  실패: {test 실패 — 핵심 오류 한 줄 / TC-003 이 코드에 없음 등}
  기록: {docs/_gate/build/T-NNN-*.log}
  개발자 의견: {설계 문제 의심 여부 한 줄}
```

## 설계 결함 화면

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
설계 문제 보고 BI-{NNN} (발견: {T-NNN})
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
무엇이: {내용 — 쉬운 말로}
증거: {명령과 출력 요약 한두 줄}
영향: {영향 Task 와 그 뒤 Task 수 / 전체}
설계를 고치면: {바뀔 문서}를 수정하고 설계를 다시 승인받습니다. 이미 끝난 Task 중 근거가 바뀐 것은 다시 검증합니다.
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 구현 차이 화면

```
설계와 다르게 구현된 것 {k}건
  - BI-{NNN} {T-NNN}: {내용}
설계를 정정하면 설계 문서가 실제 코드와 맞고, 다시 승인받습니다.
기록으로 두면 설계 문서는 그대로이고 차이는 issues.md 에 남습니다.
```

## 사람 확인 화면

질문 창이 대화 본문을 가리므로 **아래 내용을 질문 안에 넣는다** (본문에만 쓰지 않는다).

```
사람이 확인할 시나리오 ({i}/{m}) — 자세한 절차: docs/07-test/test-report.md "사람 확인 목록"
TC-{NNN} {제목}
  앱 실행: {app/ 에서 실행할 명령} → {주소}
  대상: {수동 사유의 브라우저·기기}
  절차: {요약 2~3줄}
  기대 결과: {기대 결과}
```

## 화면 시험 안내 (시험 시작 때)

```
화면 시험: {브라우저와 버전}, headless, 실제 서버({명령}, {주소})로 실행합니다.
증거: 결과 파일(TC 별), 실패 시 trace·스크린샷 → docs/07-test/_evidence/
직접 보고 싶으면: app/ 에서 {명령} --headed (증거는 아닙니다)
```

## 인수 승인 화면

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
인수 확인: {프로젝트명}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
시험 시나리오 {c}개: 통과 {p} · 면제 {w}
  └ 면제: {TC 제목 — 사유, 한 줄씩}
자동 시나리오 판정: TC 별 (테스트 결과 파일) | ⚠ 전체 실행 결과로만 (결과 파일 없음, TST-08)
인수 기준 {n}/{N} 통과로 확인
  └ 시나리오가 모두 면제된 기준: {없음 | 목록}
설계와 다른 점(기록으로 둠): {없음 | 목록}
하네스 임시 패치(원본 미반영): {없음 | 목록}
남은 보고: {없음 | 목록}
증거: docs/07-test/_evidence/{최근 실행}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

선택지: **인수 승인** / **수정 요청**.
