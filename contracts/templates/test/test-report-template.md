# 07-test/test-report.md 템플릿

시험자(`build-tester`)가 초안을 쓰고, 사람이 확인할 시나리오(`manual`)의 결과와 확인자는 허브가 사용자에게 물어 채운다.
게이트(`TST-*`)가 `시나리오 결과` 표를 읽는다.

```markdown
# 시험 보고서

> 작성일: {YYYY-MM-DD}
> 시험 실행: docs/_gate/test.json (증거: docs/07-test/_evidence/)

## 요약

- 시나리오 {N}개: 통과 {a} · 실패 {b} · 실행 불가 {c} · 면제 {d}
- 자동 실행: {명령들} → {통과|실패|실행 불가} (증거 경로). 판정: TC 별(결과 파일) | 전체 실행 결과로만
- 화면 시험: {브라우저·버전}, headless, 실제 서버({명령}). 실패 시 trace·스크린샷: {_evidence 경로}
- 인수 기준: {n}/{N} 확인됨

## 시나리오 결과

| TC | 실행 | 결과 | 증거 | 확인자 | 비고 |
|----|------|------|------|--------|------|
| TC-001 | cli | 통과 | docs/07-test/_evidence/run-20261028-150102.log, app/tests/save.test.js | - | |
| TC-005 | manual | 통과 | 사용자 확인 (2026-10-28) | 홍길동 | 실기기 20회 측정 P95 0.8초 |
| TC-006 | browser | 면제 | - | - | 사유: 시험 환경 없음 (waivers.md 2026-10-28) |

## 탐색 시험

{계획에 없던 확인: 설계와 코드가 다른 곳, 화면 확인 의견(참고). 일회성 확인은 증거 위치와 "자동 회귀 시험에 남지 않음"을 적는다}

## 사람 확인 목록

| TC | 앱 실행(명령·주소) | 대상 | 절차 | 기대 결과 |
|----|-------------------|------|------|-----------|

## 발견 사항

{발견한 문제는 docs/06-build/issues.md 에 BI-NNN 으로 올리고 여기에는 ID 만}

## 검증 기록
```

- 요약의 `시나리오 N개: 통과 a · 실패 b · 실행 불가 c · 면제 d` 줄은 결과 표와 같아야 한다 (`TST-10`). 수동 결과를 표에 더하면 이 줄도 고친다.
- 시험 뒤에 앱 코드·시험 계획·명령 표가 바뀌면 다시 시험한다 (`TST-09`).
- `결과`: `통과` / `실패` / `실행 불가` / `면제`. 실행 불가는 통과가 아니다.
- 자동 TC(`cli`·`browser`·`device`)의 `통과`는 최근 시험 실행(`docs/_gate/test.json`)이 통과했고, 결과 파일(JUnit XML)에서 그 TC 가 통과일 때만 쓸 수 있다 (`TST-02`). 결과 파일이 없는 설계는 TC ID 가 앱 코드에 있는지로 대신하고 `TST-08` 경고가 남는다.
- `manual`의 `통과`에는 `확인자`(사용자)를 쓴다. 시험자가 대신 통과시키지 않는다 (`TST-03`).
- `면제`는 `비고`에 사유를 쓴다. 인수 기준의 시나리오가 모두 면제면 경고다.
