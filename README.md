# 일정관리 (self-canban)

내 PC 한 대에서 혼자 쓰는 **칸반 보드 일정 관리 프로그램**입니다.
개발 버그나 할 일을 카드로 적어 두고, **할 일 → 진행 중 → 완료**로 옮기면서 진행 상황을 한 화면에서 봅니다. 마감일이 있는 카드는 **캘린더**로도 볼 수 있습니다.

- 회원가입, 로그인, 서버가 **없습니다**. 입력한 내용은 **내 PC 안에만** 저장됩니다.
- **인터넷이 없어도** 모두 동작합니다.
- Windows 11 (64비트) 용입니다.

---

## 1. 이 프로그램으로 할 수 있는 것

| 기능 | 설명 |
|---|---|
| 카드 만들기 | 제목, 종류(개발 버그 / 할 일), 상세 설명, 마감일, 우선순위, 추가 메모를 적습니다 |
| 상태 옮기기 | 카드를 끌어서 다른 칸으로 놓거나, 카드의 메뉴로 옮깁니다 |
| 진행 기록 | 카드마다 "검토해 보니 이랬다", "추가 이슈가 생겼다" 같은 기록을 날짜와 함께 남깁니다 |
| 캘린더 | 마감일이 있는 카드를 달력으로 봅니다. 달력의 카드를 끌어 다른 날짜에 놓으면 마감일이 바뀝니다 |
| 보관함 | 끝난 카드를 보드에서 치워 두는 곳입니다. 나중에 다시 찾아볼 수 있습니다 |
| 검색·걸러보기 | 제목으로 검색하고, 종류나 우선순위로 걸러 봅니다 |
| 마감 지난 표시 | 마감일이 지났는데 아직 끝나지 않은 카드를 눈에 띄게 보여 줍니다 |
| 밝은 화면 / 어두운 화면 | 처음에는 밝은 화면이고, 원하면 어두운 화면으로 바꿉니다 |

## 2. 설치하고 실행하기 (처음 한 번만)

설치 프로그램은 없습니다. **압축 파일을 풀고 `일정관리.exe`를 실행하면 끝**입니다.

### 2-1. 내려받기
1. 이 저장소 첫 화면 오른쪽의 **Releases**(릴리스)를 누릅니다.
2. 가장 위에 있는 항목의 **Assets** 안에서 `self-canban-windows-x64.zip`을 눌러 내려받습니다.
   - 파일 크기가 크니(약 150MB 안팎) 시간이 걸릴 수 있습니다.

### 2-2. 압축 풀기
1. 내려받은 zip 파일에서 마우스 오른쪽 버튼 → **모두 압축 풀기**를 누릅니다.
2. 풀 위치는 어디든 괜찮습니다. 예: `C:\프로그램\일정관리`
3. 압축을 푼 폴더 안에 **`win-unpacked`** 폴더가 있고, 그 안에 `일정관리.exe`가 있습니다.

> ⚠️ **`일정관리.exe` 파일만 따로 옮기면 실행되지 않습니다.** `win-unpacked` 폴더 안의 파일들이 모두 같이 있어야 합니다. 폴더째로 옮기거나 보관하세요.

### 2-3. 실행하기
1. `win-unpacked` 폴더 안의 **`일정관리.exe`** 를 더블클릭합니다.
2. 처음 실행할 때 파란 **"Windows의 PC 보호"** 창이 뜰 수 있습니다. 이 프로그램은 회사 인증서로 서명하지 않아서 생기는 정상적인 경고입니다.
   1. 창에서 **추가 정보**를 누릅니다.
   2. 나타난 **실행** 버튼을 누릅니다.
3. 잠시 뒤 "일정관리" 창이 열립니다. 이제 아무것도 없는 빈 보드가 보입니다.

### 2-4. 바탕화면에 바로 가기 만들기 (선택)
`일정관리.exe`에서 마우스 오른쪽 버튼 → **바로 가기 만들기**를 누르고, 만들어진 바로 가기를 바탕화면으로 옮깁니다.

## 3. 사용 방법 (처음 쓰는 분을 위한 순서)

화면 왼쪽에는 메뉴(사이드바)가 있고, 오른쪽이 본 화면입니다.

```
┌────────────┬────────────────────────────────────────────┐
│ 일정관리   │  [검색]                      [카드 만들기]  │
│ 보드  (N)  ├────────────┬────────────┬──────────────────┤
│ 캘린더     │  할 일     │  진행 중   │  완료            │
│ 보관함 (N) │  ┌──────┐  │  ┌──────┐  │  ┌──────┐        │
│ ─────────  │  │ 카드 │  │  │ 카드 │  │  │ 카드 │        │
│ 종류       │  └──────┘  │  └──────┘  │  └──────┘        │
│ 우선순위   │            │            │                  │
│ 화면 밝기  │            │            │                  │
│ 저장 상태  │            │            │                  │
└────────────┴────────────┴────────────┴──────────────────┘
```

### 3-1. 카드 만들기
1. 오른쪽 위의 **카드 만들기** 버튼을 누릅니다.
2. **제목**을 적습니다. 제목은 꼭 있어야 합니다. 나머지는 비워 둬도 됩니다.
3. 필요하면 아래 항목을 고릅니다.
   - **종류**: `개발 버그` 또는 `할 일` (고르지 않으면 `할 일`)
   - **상태**: `할 일`(기본) 또는 `진행 중`. 이미 시작한 일이면 처음부터 `진행 중`으로 만들 수 있습니다
   - **마감일**: 칸 오른쪽의 달력 모양을 눌러 날짜를 고르거나, 직접 숫자로 적습니다. 지우면 마감일이 없는 카드가 됩니다
   - **우선순위**: `없음`, `낮음`, `중간`, `높음`
   - **상세 설명**, **추가 메모**: 자유롭게 적습니다
4. **저장** 버튼을 누릅니다. 카드가 선택한 상태의 칸에 나타납니다.

> 제목을 비우고 저장하면 오류 문구가 나오고 카드가 만들어지지 않습니다. 없는 날짜(예: 2월 30일)를 마감일로 넣어도 마찬가지입니다.

### 3-2. 카드 상태 옮기기
카드는 진행되는 만큼 칸을 옮깁니다. 방법은 두 가지입니다.
- **끌어서 놓기**: 카드를 마우스로 누른 채 다른 칸 위로 끌어 놓습니다.
- **메뉴로 옮기기**: 카드의 메뉴(점 세 개 모양)를 눌러 **상태 이동**에서 옮길 칸을 고릅니다.

완료한 카드를 다시 진행 중이나 할 일로 되돌릴 수도 있습니다.

### 3-3. 카드 열어서 고치기 · 진행 기록 남기기
1. 카드를 누르면 상세 창이 열립니다.
2. 제목, 마감일 같은 내용을 고치고 **저장**을 누릅니다.
3. 창 아래쪽 **진행 기록**에서 기록을 남깁니다.
   1. **기록 내용** 칸에 적습니다. 예: "원인은 날짜 계산 오류로 보임"
   2. **기록 추가**를 누릅니다.
   3. 기록은 남긴 순서대로 쌓이고, 남긴 때의 카드 상태(할 일 / 진행 중 / 완료)가 함께 표시됩니다.
   - 기록은 카드를 저장한 뒤에 남길 수 있습니다.

### 3-4. 카드 삭제하기
1. 카드를 열어 **삭제**를 누릅니다.
2. 확인 줄이 나오면 **삭제 확인**을 눌러야 지워집니다. 카드와 그 카드의 진행 기록이 함께 사라지고 **되돌릴 수 없습니다**.
3. 취소하면 카드가 그대로 남습니다.

### 3-5. 캘린더로 보기
1. 왼쪽 메뉴의 **캘린더**를 누릅니다.
2. 마감일이 있는 카드가 그 날짜 칸에 보입니다. 마감일이 없는 카드는 캘린더에 나오지 않고 보드에서만 보입니다.
3. 위쪽에서 **월 / 주** 보기를 바꾸고, 화살표로 달이나 주를 이동합니다. **오늘로 이동**을 누르면 오늘로 돌아옵니다.
4. 카드를 누르면 상세 창이 열립니다.
5. **마감일 바꾸기**: 카드를 끌어서 다른 날짜 칸에 놓으면 마감일이 그 날짜로 바뀝니다. 같은 칸에 놓으면 아무 일도 일어나지 않습니다.
6. 하루에 카드가 많으면 "+N건 더 보기"로 나머지를 볼 수 있습니다.

### 3-6. 끝낸 카드 보관하기
1. 완료 칸의 카드에서 **보관**을 누르고 **보관 확인**을 누릅니다.
2. 카드가 보드와 캘린더에서 사라지고 **보관함**으로 갑니다. 완료한 카드만 보관할 수 있습니다.
3. 왼쪽 메뉴의 **보관함**에서 보관한 카드를 찾아보고 내용을 읽을 수 있습니다. 보관한 카드는 고칠 수 없고, 삭제만 할 수 있습니다.

### 3-7. 검색하고 걸러 보기
- 위쪽 **검색** 칸에 글자를 입력하면 제목에 그 글자가 들어 있는 카드만 보입니다.
- 왼쪽 메뉴의 **종류**, **우선순위**에서 항목을 고르면 그 조건에 맞는 카드만 보입니다. 처음에는 두 곳 모두 **전체**가 선택되어 있고(조건 없음), **전체**를 다시 고르면 조건이 풀립니다.
- 조건을 한꺼번에 풀려면 **조건 모두 지우기**를 누릅니다.
- 보관함에서도 같은 방법으로 찾습니다.

### 3-8. 마감이 지난 카드
마감일이 오늘보다 앞이고 아직 완료하지 않은 카드는 삼각형 표시와 "N일 지남" 글자로 눈에 띄게 보입니다. 완료한 카드는 마감이 지났어도 표시되지 않습니다.

### 3-9. 화면 밝기 바꾸기
왼쪽 메뉴 아래쪽 **화면 밝기**에서 **밝은 판** / **어두운 판**을 고릅니다. 고른 화면은 다음에 열 때도 유지됩니다.

## 4. 내 데이터는 어디에 저장되나요?

- 카드를 만들거나 옮길 때마다 **자동으로 저장**됩니다. 따로 저장 버튼을 누르지 않아도 됩니다.
- 왼쪽 메뉴 맨 아래에 **내 PC에 저장됨**이 보이면 저장이 끝난 것입니다. **저장 중**이 보일 때는 잠깐 기다리세요.
- 저장 위치는 다음 폴더입니다.

```
C:\Users\<내 사용자 이름>\AppData\Roaming\self-canban\
```

빠르게 열려면: 키보드의 **윈도우 키 + R** → `%APPDATA%\self-canban` 입력 → 확인.

이 폴더 안의 **`kanban-data.json`** 파일 하나에 모든 카드와 기록이 들어 있습니다.

### 데이터 백업하기 (권장)
이 프로그램에는 백업 기능이 없습니다. PC가 고장 나면 데이터를 되살릴 방법이 없으니, 가끔 직접 복사해 두세요.
1. 프로그램을 **닫습니다**.
2. `%APPDATA%\self-canban` 폴더를 엽니다.
3. `kanban-data.json` 파일을 USB나 클라우드 등 다른 곳에 복사해 둡니다.

### 다른 PC로 옮기기 / 백업에서 되살리기
1. 새 PC에서 프로그램을 한 번 실행했다가 **닫습니다**(폴더가 만들어집니다).
2. 복사해 둔 `kanban-data.json`을 `%APPDATA%\self-canban` 폴더에 **덮어씁니다**.
3. 프로그램을 다시 실행합니다.

## 5. 문제가 생겼을 때

| 증상 | 해결 방법 |
|---|---|
| 실행이 안 되고 "Windows의 PC 보호"가 뜬다 | **추가 정보 → 실행**을 누르세요 (2-3 참고) |
| `일정관리.exe`를 더블클릭해도 아무 일이 없다 | `win-unpacked` 폴더 안의 다른 파일이 지워지지 않았는지 확인하세요. 압축을 다시 풀어 폴더 전체를 쓰세요 |
| "저장하지 못했습니다"가 뜬다 | 입력한 내용은 화면에 남아 있습니다. 디스크 공간이나 폴더 권한을 확인하고 **다시 저장**을 누르세요 |
| "저장된 데이터를 읽지 못했습니다"가 뜬다 | 프로그램을 닫고 `%APPDATA%\self-canban` 폴더의 `kanban-data.json`을 다른 이름으로 바꾼 뒤 다시 열면 직전 저장본(`kanban-data.json.bak`)으로 열립니다. 화면의 안내 문구도 같은 방법을 알려 줍니다. 읽지 못한 데이터는 새 저장으로 덮어쓰이지 않습니다 |
| 이전에 어두운 화면으로 바꿨는데 계속 어둡다 | 저장된 선택이 우선합니다. 왼쪽 메뉴에서 **밝은 판**을 고르세요 |
| 같은 프로그램을 두 번 실행했다 | 같은 데이터를 두 창이 쓰면 마지막에 저장한 쪽 내용이 남을 수 있으니 한 번에 하나만 쓰세요 |

### 프로그램 지우기
`일정관리` 폴더(압축을 푼 폴더)를 삭제하면 프로그램이 지워집니다. 내 카드 데이터는 지워지지 않고 `%APPDATA%\self-canban` 폴더에 남아 있으니, 데이터까지 지우려면 그 폴더도 삭제하세요.

## 6. 개인정보와 보안

- 이 프로그램은 **네트워크에 연결하지 않습니다.** 입력한 내용은 PC 밖으로 나가지 않습니다.
- 계정도, 광고도, 통계 수집도 없습니다.
- 글꼴은 프로그램 안에 들어 있어 따로 내려받지 않습니다.

## 7. 개발자를 위한 안내 (소스를 받아서 직접 실행·수정하려는 분)

프로그램만 쓰는 분은 이 아래를 읽지 않아도 됩니다. 이 장은 **GitHub에서 소스를 내려받아 내 PC에서 실행하고, 고치고, 직접 포장**하기까지를 순서대로 설명합니다.

> 소스로 실행하려면 **인터넷이 필요한 단계가 한 번 있습니다**(패키지와 Electron 실행 파일을 내려받는 `npm ci`). 그 뒤 앱 자체는 오프라인에서 동작합니다. `node_modules` 폴더는 저장소에 들어 있지 않으므로 내려받은 직후에는 반드시 설치부터 해야 합니다. 설치 없이 `npm run dev`를 하면 오류가 납니다.

### 7-1. 준비물 설치 (처음 한 번)

| 준비물 | 용도 | 확인 명령 |
|---|---|---|
| **Windows 11** | 이 프로젝트는 Windows 기준으로 만들고 시험했습니다 | |
| **Node.js 22.13 이상** (LTS 권장) | 실행·빌드. `npm`이 함께 설치됩니다 | `node --version` |
| **Git** | 소스 내려받기 | `git --version` |
| 편집기 (예: VS Code) | 코드 수정 (선택) | |

1. Node.js는 https://nodejs.org 에서 **LTS** 버전을 받아 설치합니다. 만든 환경은 Node 22.23.2, npm 10.9.8입니다.
2. 설치가 끝나면 **새 터미널**(PowerShell 또는 명령 프롬프트)을 열어 `node --version`이 `v22.13.0` 이상으로 나오는지 확인합니다. 설치 직후 열려 있던 터미널에서는 인식되지 않을 수 있으니 터미널을 닫고 다시 여세요.
3. Node 버전이 22.13보다 낮으면 `npm ci`에서 버전 경고나 오류가 날 수 있습니다.

### 7-2. 소스 내려받기

방법 A. Git으로 내려받기 (권장)
```bash
git clone https://github.com/chr0812/self-canban-electron.git
cd self-canban-electron
```

방법 B. Git 없이 내려받기: 저장소 페이지에서 **Code → Download ZIP**을 눌러 받고 압축을 풉니다. 이후 명령은 같습니다.

폴더 경로에 한글이나 공백이 있어도 동작하지만, 문제가 생기면 `C:\work\self-canban-electron`처럼 짧은 영문 경로로 옮겨 보세요.

### 7-3. 패키지 설치 (필수, 몇 분 걸립니다)

```bash
cd app
npm ci
```

- `app` 폴더 안에서 실행해야 합니다. (저장소 맨 위 폴더에도 `package.json`이 있지만 그것은 기획·구현 절차 도구용이고, 앱은 `app/`에 있습니다.)
- `npm ci`는 `package-lock.json`에 적힌 **정확한 버전 그대로** 설치합니다. 처음에는 `npm install` 대신 이 명령을 쓰세요.
- 설치 중에 Electron 실행 파일(수백 MB)을 인터넷에서 내려받으므로 시간이 걸립니다. 끝나면 `app/node_modules` 폴더가 생깁니다.
- 끝에 `npm warn`이 몇 줄 나와도 오류가 아니면 괜찮습니다.

### 7-4. 실행해 보기

```bash
npm run dev
```

- 잠시 뒤 "일정관리" 창이 열립니다. 이것이 개발용 실행입니다.
- 코드를 고치고 저장하면 화면은 바로 반영되고, 메인 쪽 코드를 고치면 앱이 자동으로 다시 뜹니다.
- 끝내려면 터미널에서 **Ctrl + C**를 누르거나 창을 닫습니다.
- **개발용 실행의 데이터는 `%APPDATA%\self-canban-dev` 폴더에 저장됩니다.** 포장해서 쓰는 실제 앱의 데이터(`%APPDATA%\self-canban`)와 섞이지 않습니다.

빌드 결과물로 실행해 보려면(포장 전의 실제 코드와 같은 조건):
```bash
npm run build
npm run start
```

### 7-5. 명령 정리 (모두 `app/` 폴더에서)

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발용 실행 (코드 수정이 바로 반영) |
| `npm run build` | 타입 검사 후 빌드. 결과는 `app/out/` |
| `npm run start` | 빌드 결과를 실행 (먼저 `npm run build`) |
| `npm run lint` | 코드 검사 (ESLint) |
| `npm run format` | 코드 모양 자동 정리 (Prettier). 파일이 바뀝니다 |
| `npm test` | 단위 시험 (Vitest). 창이 뜨지 않고 몇 초 걸립니다 |
| `npm run test:e2e` | 화면 시험 (Playwright). 빌드 후 **실제 앱 창이 여러 번 열렸다 닫힙니다**. 약 2~3분 걸리고, 그 동안 마우스·키보드를 쓰지 않는 것이 좋습니다 |
| `npm run package` | Windows용 실행 폴더로 포장 (아래 7-7) |

시험 결과는 `app/reports/`, `app/test-results/`에 생기고 저장소에는 올라가지 않습니다.

### 7-7. 포장해서 실행 파일 만들기

```bash
cd app
npm run build
npm run package
```

- 결과: `app/release/win-unpacked/일정관리.exe` (폴더 전체가 필요합니다). 폴더째로 압축해서 배포합니다.
- 설치 파일(`.exe` 설치기)이 아니라 **실행 폴더**를 만드는 설정입니다. 설치 파일이 필요하면 `electron-builder.yml`의 `win.target`을 바꿔야 합니다.
- 코드 서명이 없어서 받는 사람 PC에서 "Windows의 PC 보호" 경고가 뜹니다(2-3 참고). 앱 아이콘은 기본 Electron 아이콘입니다.
- 포장 결과(`app/release/`)는 저장소에 올라가지 않습니다. 배포는 GitHub의 **Releases**에 zip으로 올립니다.

**포장 중 `EPERM`/`EBUSY` 오류가 나면:** 폴더를 감시하는 프로그램이 포장 중 만들어지는 파일을 잡고 있어서 생깁니다. 포장 결과를 프로젝트 밖으로 보내면 해결되는 경우가 많습니다.
```bash
npx electron-builder --win --dir --config electron-builder.yml --config.directories.output=C:/출력/폴더
```

### 7-8. 자주 고치는 곳

| 하고 싶은 일 | 고칠 파일 (`app/src/...`) |
|---|---|
| 화면에 보이는 글자(버튼 이름, 안내 문구) | `renderer/src/text/labels.ts` |
| 색, 글자 크기, 밝은/어두운 판 색 | `renderer/src/styles/tokens.css` |
| 처음 열리는 창 크기 | `main/app/window-factory.ts` |
| 우선순위·상태 같은 선택지 | `shared/constants.ts` |
| 카드 규칙(검증, 마감 지남 판정) | `shared/domain/` |
| 저장 파일 형식, 이전 버전 데이터 읽기 | `main/store/` |
| 보드·캘린더 화면 | `renderer/src/features/board/`, `features/calendar/` |

고친 뒤에는 `npm run lint`, `npm test`, `npm run test:e2e`를 차례로 돌려 확인하세요. 저장 형식을 바꾸면 이전 버전의 데이터를 읽을 수 있도록 `main/store/migrations/`에 변환 단계를 더해야 합니다.

### 7-9. `docs/`와 기획·구현 도구 (읽어 두면 좋은 것)

이 프로젝트는 인터뷰 → PRD → 명세 → 설계 → 구현 → 시험 → 인수 승인의 절차를 거쳐 만들었고, 그 기록이 `docs/`에 있습니다.

| 폴더 | 내용 |
|---|---|
| `docs/01-interview` ~ `03-prd` | 무엇을, 왜 만드는지 |
| `docs/04-spec/spec.md` | 기능 요구사항(FR), 인수 기준(AC) 전체 |
| `docs/05-design/` | 기술 스택, 데이터·API, 화면(와이어프레임), 구조, 파일 지도, 시험 계획, 작업 목록. **먼저 `README.md`부터** 읽으세요 |
| `docs/06-build`, `07-test` | 구현 기록, 시험 보고서와 증거 |

- 단순히 코드를 고치거나 기능을 써 보려는 분은 `docs/`를 몰라도 됩니다.
- 이 절차 도구(`scripts/`, `.claude/`, `contracts/`)는 Claude Code라는 AI 코딩 도구와 함께 쓰도록 만든 것입니다. 사람이 직접 쓸 때는 `node scripts/gate.js status`로 현재 진행 상태를 볼 수 있습니다. 쓰지 않아도 앱은 `app/`만으로 빌드·실행됩니다.
- 앱 코드를 고치면 `docs/07-test`의 인수 승인이 낡은 것으로 표시될 수 있습니다. 절차를 따르는 프로젝트가 아니라면 무시해도 됩니다.

### 7-10. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `npm`이나 `node`를 찾을 수 없다고 나온다 | Node.js 설치 후 **터미널을 새로 열었는지** 확인 |
| `npm ci`가 `engines` 버전 경고·오류를 낸다 | `node --version`이 22.13 이상인지 확인 |
| `npm ci` 중 Electron 다운로드에서 멈추거나 실패한다 | 인터넷·프록시·방화벽 확인. 회사망이면 프록시 설정(`npm config set proxy ...`)이나 Electron 미러(`ELECTRON_MIRROR` 환경 변수)가 필요할 수 있습니다 |
| `npm run dev`가 `electron-vite`를 찾지 못한다 | `app/` 폴더에서 `npm ci`를 했는지 확인 (`app/node_modules`가 없으면 설치 전입니다) |
| `package.json`을 찾을 수 없다는 오류 | `cd app`을 했는지 확인 |
| 화면 시험(`test:e2e`)이 이상하게 실패한다 | 시험 중에 마우스·키보드를 쓰거나 같은 앱을 따로 띄워 두지 않았는지 확인하고 다시 실행. 시험은 한 번에 하나씩 돕니다 |
| 포장 중 `EPERM` / `EBUSY` | 위 7-7의 출력 위치 변경 방법 |
| 실행 파일 경로에 `%` 같은 특수 문자가 있다 | 화면이 열리지 않는 문제를 고쳐 두었지만, 의심되면 짧은 영문 경로로 옮겨 보세요 |

### 7-11. 사용한 주요 기술과 라이선스

- Electron 45, React 19, TypeScript 6, electron-vite 6 / Vite 8, Vitest 5(단위 시험), Playwright 1.64(화면 시험), electron-builder 26(포장). 정확한 버전은 `app/package.json`과 `app/package-lock.json`에 있습니다.
- 글꼴 SUIT는 SIL Open Font License 1.1로 배포됩니다. 라이선스 원문은 소스의 `app/src/renderer/src/styles/fonts/SUIT-LICENSE.txt`와 포장본의 `resources/licenses/SUIT-LICENSE.txt`에 있습니다.
