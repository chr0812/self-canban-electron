# Competitor Analysis Guide

경쟁사/유사 서비스 분석 절차와 출력 형식을 정의한다.

## 수행 절차

### 1. 경쟁사 식별

- 직접 경쟁: 동일 문제를 동일 방식으로 해결
- 간접 경쟁: 동일 문제를 다른 방식으로 해결
- 잠재 경쟁: 인접 도메인에서 확장 가능성

식별 기준:
- standard depth: 직접 3~5개
- deep depth: 직접 5~7개 + 간접 2~3개

### 2. 개별 분석 항목

각 경쟁사:
- **서비스명 + URL**
- **핵심 기능** (3개): 가장 많이 사용되는 / 홍보하는 기능
- **차별점**: 다른 경쟁사 대비 고유한 점
- **약점**: 사용자 불만, 한계
- **타겟 사용자**: 주요 고객층
- **비즈니스 모델**: 수익 구조 (deep만)
- **시장 점유율/규모**: 가능하면 (MAU, 다운로드 수 등)

### 3. 비교 분석

공통 기능 매트릭스:
- 주요 기능 목록 × 경쟁사 지원 여부
- 가격/플랜 비교 (해당 시)

### 4. SWOT 분석 (deep만)

각 경쟁사별 또는 시장 전체:
- Strengths / Weaknesses / Opportunities / Threats

### 5. 시사점 도출

이 프로젝트가 취할 수 있는 포지셔닝:
- 차별화 포인트 후보
- 피해야 할 접근
- 벤치마킹할 기능

## WebSearch 키워드 패턴

```
"{도메인} 앱 추천 {현재연도}"
"{도메인} 서비스 비교"
"{경쟁사명} 리뷰"
"{경쟁사명} vs {경쟁사명}"
"{도메인} 시장 점유율"
```

## 개별 분석

- **핵심 기능**: (1) ... (2) ... (3) ...
- **차별점**: ...
- **약점**: ...
- **타겟 사용자**: ...

- **규모**: MAU {N} / 다운로드 {N} (가능하면)

...

## 기능 비교 매트릭스

| 기능 | {A} | {B} | {C} | 우리 (계획) |

- {함정/피해야 할 접근}

## 규칙

- 최소 3개 경쟁사 분석 (deep은 5개 이상)
- 각 경쟁사에 출처(URL) 또는 [일반 지식 폴백] 명시
- 단일 출처에만 의존 금지 (교차 확인)
- "우리 (계획)" 컬럼은 빈 칸 또는 ?로 — 확정하지 않음
