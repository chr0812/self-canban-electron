# 역할 공통 규약

`.claude/agents/`의 역할 에이전트가 모두 따르는 규약이다. 산출물 규약은 `contracts/artifact-contract.md`가 우선한다.
역할은 **무엇을 만드는지만** 안다. 언제, 어떤 순서로, 누구와 동시에 실행되는지는 모른다 (오케스트레이터와 단계 계획이 정한다).

## 입력과 출력

- 입력은 호출 때 받은 **파일 경로**다. 내용이 프롬프트에 붙어 오지 않으니 직접 읽는다. 입력 파일이 없으면 만들어 내지 말고 중단해서 보고한다.
- 산출물은 **지정된 출력 파일에만** 쓴다. 다른 역할의 산출물은 읽기만 하고 고치지 않는다 (같은 시간에 다른 역할이 실행 중일 수 있다).
- 호출에 "불일치 목록"이나 "수정 지시"가 있으면 기존 출력 파일에서 **해당 부분만** 고친다.

## 질문하지 않는다

- 사용자에게 질문할 수 없다. 판단이 서지 않으면 산출물에 `## 결정 필요` 섹션을 두고 선택지와 권고안을 적는다 (없으면 "없음").
- 입력에 없는 사실·수치·고유명사를 만들지 않는다. 모르면 `결정 필요`에 올린다.

## 호출하지 않는다

- 다른 에이전트나 스킬을 호출하지 않는다.

## 문서 규칙

- 헤딩에 번호를 붙이지 않는다. 문서 머리에 `> 작성일: YYYY-MM-DD` 줄을 둔다.
- 요구사항 ID(FR, NFR, SCR, UC 등)는 `spec.md`의 것을 그대로 쓴다. 새 ID를 만들지 않는다 (`T-NNN`만 예외).
- 문서 안에 **승인 여부나 진행 상태를 적지 않는다.** 승인 뒤에 문서가 바뀌면 승인이 무효가 되기 때문이다.
- 구현(코드 작성)은 하지 않는다. 설계 문서의 예시 코드·시그니처는 괜찮다. (예외: 구현 단계 역할은 아래 절)
- 문서 끝에 `## 검증 기록` 섹션을 두고 자체 점검 결과를 적는다.
- 웹 검색을 쓰는 역할은 근거마다 출처 URL을 적고, 검색하지 못했으면 그 사실을 적는다.
- **게이트를 피하려고 형식을 바꾸지 않는다.** ID 를 코드 블록에 숨기거나 표기를 비틀지 않는다. 삭제한 ID 는 `## 변경 이력` 표의 `삭제 ID` 열에 적는다 (게이트가 그 열을 결번·정의 없는 ID 검사에서 뺀다). 규칙이 맞지 않으면 `결정 필요`로 돌려준다.
- 설계 역할은 지정된 문서 외의 파일·폴더를 만들지 않는다 (`docs/05-design/` 안에 앱 폴더를 미리 만들지 않는다 — 게이트 `FMT-05`).
- 하네스 파일(`scripts/`, `.claude/`, `contracts/`)을 고치지 않는다.

## 구현 단계 역할 (`build-developer`, `build-tester`)

- 코드는 앱 루트 `app/` 안에만 쓴다. `docs/`(설계·명세·기록)는 읽기만 한다. **승인된 설계를 고치지 않는다.**
- 완료를 스스로 선언하지 않는다. 완료는 오케스트레이터가 `node scripts/build.js verify`로 판정한다. 역할은 명령을 직접 돌려 볼 수 있다.
- 설계대로 할 수 없거나 설계와 다르게 했으면 `결정 필요`로 돌려준다. 유형 제안(코드 결함 / 구현 차이 / 설계 결함 / 명세 결함 / 하네스 결함)과 영향 Task, 증거(명령과 출력 요약)를 함께 쓴다. 분류와 처리는 오케스트레이터가 정한다. 설계 문서끼리 서로 다르게 말하면 설계 결함이다.
- 시험 시나리오를 구현한 테스트는 **각 테스트(testcase) 이름에 TC ID** 를 넣는다 (`build.js`가 결과 파일의 testcase 에서 TC 를 찾는다. 주석은 인정하지 않는다).
- 직접 띄운 서버·프로세스는 PID 를 적고, 끝나기 전에 그 PID 만 종료한다. 다른 프로세스를 끄지 않는다.
- 진행 기록(`build.js start`·`handoff`·`verify`·`issue`)은 오케스트레이터가 한다.
- git 커밋·푸시를 하지 않는다. 의존성 추가는 설계(`01-tech-stack.md`)에 있는 것만 한다.

## 최종 메시지 (메인에 돌려주는 것)

다음만 쓴다. **산출물 본문을 메시지에 복사하지 않는다.**

1. 산출물 파일 경로
2. 결정 요약 5줄 이내
3. `결정 필요` 항목 수와 핵심 항목
4. 못한 것, 확인하지 못한 것 (있는 그대로)
