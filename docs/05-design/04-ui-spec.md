## 플랫폼 정보

- **유형**: webapp (화면 기술은 Electron 렌더러, 웹 표준 HTML/CSS + React 19). 실행 형태는 데스크톱 앱이다
- **타겟 디바이스**: Windows 11 데스크톱 한 대, 마우스·키보드. 기본 창 1280x920(제목 표시줄을 포함한 바깥 크기. 설계 기본값이고 구현 단계에서 측정해 확정한다, `결정 필요` 12). 터치·모바일·태블릿은 범위 밖이다 (CON-001, ASM-003)
- **적용 체크리스트**: ui-checklist-webapp (모바일 항목은 `해당 없음`으로 기록한다)
- **언어**: 화면 문구와 날짜 표기는 한국어 (ASM-016)

### 기술 스택 연계

- 디자인 시스템: **커스텀 (CSS 변수 토큰 + 직접 만든 컴포넌트)** 이다. 근거: 시안 V-A는 4px 모서리, 62px 카드, 12~16px 글자, 따뜻한 색 체계(색 조정, 아래 `디자인 방향`)라서 범용 컴포넌트 라이브러리의 기본값(둥근 모서리, 파랑 강조, 넉넉한 여백)을 거의 전부 덮어써야 한다. `01-tech-stack.md`의 패키지 표에 UI 라이브러리가 없고, 화면 수가 4개라 직접 만드는 비용이 작다
- 호환 라이브러리: 추가하지 않는다. 모달은 브라우저 내장 `<dialog>`(Chromium 156 지원, 포커스 가두기와 Esc 닫기 내장), 팝업·메뉴는 내장 `popover` 속성 또는 직접 구현, 끌어다 놓기는 HTML5 Drag and Drop을 쓴다(보드의 카드와 캘린더의 칩 모두). 마감일 날짜 선택은 브라우저 기본 `<input type="date">`를 쓴다(날짜 선택 라이브러리 없음, NFR-001). 이것으로 부족해 라이브러리가 필요해지면 `01-tech-stack.md` 패키지 표에 먼저 추가한 뒤 쓴다
- 아이콘: 앱에 포함하는 인라인 SVG 컴포넌트 약 16개(14px 격자, 선 굵기 1.3~1.6). 아이콘 라이브러리를 새로 들이지 않는다 (NFR-001, 패키지 표 불변)
- 글꼴: 앱에 포함한 woff2를 `@font-face`로 불러온다. 외부 주소와 CDN 없음 (NFR-001)

### 입력/폼

| 항목 | 결정 | 근거 |
|------|------|------|
| 인라인 vs 모달 vs 전체 페이지 편집 | 모달 대화상자 | 보드·캘린더·보관함 세 곳에서 같은 방식으로 열고 닫으면 원래 자리로 돌아온다 (AC-030) |
| 폼 유효성 검사 시점 | 저장을 눌렀을 때 검사. 마감일은 입력 칸을 벗어날 때도 검사. 오류는 고치기 시작하면 바로 사라진다. 마감일은 날짜 선택 칸이라 없는 날짜를 값으로 내지 않으므로 오류 문구는 도메인 검증이 거절하는 값이 들어온 경우에만 보인다 | AC-002, AC-029, AC-035, AC-043 |
| 자동 저장 vs 명시적 저장 | 카드 내용은 `저장` 버튼. 진행 기록 추가와 밝기 전환은 누르는 즉시 저장 | 제목 비움 시 저장하지 않는다는 규칙(AC-035)이 명시 저장을 전제한다 |
| 멀티스텝 폼 | 없다 | 입력 항목 7개(제목, 종류, 상태, 마감일, 우선순위, 상세 설명, 추가 메모)가 한 화면에 들어간다 |
| 벌크 액션 | 없다 | 요구 없음 |

| 낙관적 업데이트 | 밝기 전환만 화면에 먼저 반영한다. 저장이 실패하면 화면은 되돌리지 않고 이번 실행 동안 선택한 판을 유지하며 실패 알림과 `다시 저장`을 보인다. 칸 이동·보관·삭제·캘린더에서 끌어 마감일 바꾸기(와 만들기·수정·기록 추가)는 낙관적으로 반영하지 않는다: 요청을 보내 사이드바에 `저장 중`을 보이고, 저장이 성공한 뒤에 화면(카드 위치, 칩 위치, 보관함 행)을 바꾼다. 저장이 실패하면 화면은 바뀌지 않고 저장 실패 알림과 `다시 저장`이 보이며 사용자는 다시 시도한다 | UC-011 Alt Flow 1(밝기 전환), AC-031, AC-046. 칸 이동·보관·삭제·마감일 끌기는 사용자 결정(낙관적 반영 없음)이다 |
| 에러 바운더리 범위 | 화면 단위. 데이터 읽기 실패는 본문 전체를 대체하는 전용 패널 | AC-032 |
| 세션 만료 | 해당 없음 | 로그인 없음 (CON-001) |
| 동시 편집 충돌 UX | 해당 없음 | 사용자 1명. 두 창 덮어쓰기는 명세가 감수했다 (범위 제외) |

## 디자인 방향

> 사용자가 시안을 보고 고른 결과다 (`docs/05-design/_variants/choice.md`). 새로 정한 방향이 아니다. 단, 사용자가 화면 설계 확인 단계에서 색 체계만 바꾸라고 해서 색을 다시 정했다 (아래 `조정`). V-B, V-C로 바꾼 것이 아니다.

- 선택: V-A (밀도형 도구). 어두운 판과 밝은 판을 함께 두고 사용자가 전환한다 (밝은 판의 색은 화면 설계가 V-A의 구성·글꼴·밀도·모서리를 유지한 채 정한다)
- 기각: V-B (사용자가 V-A를 골랐다. 기각 사유는 말하지 않았다), V-C (사용자가 V-A를 골랐다. 기각 사유는 말하지 않았다)
- 조정 (2026-11-03, 화면 설계 확인 단계): 사용자가 "전문적인 건 좋은데 너무 색조가 없다"며 색 변경을 요청했다. 구성·글꼴·밀도·모서리는 V-A를 유지하고 색 체계만 "따뜻한 분위기"로, 색 적용은 "뚜렷하게 (카드와 캘린더에도)"로 바꾼다. V-A 원 시안의 색(무채색 + 앰버)은 더 이상 기준이 아니다.
- 근거: 카드가 1년에 수백~수천 건 쌓일 수 있고(ASM-010) 세 칸이 한 화면에 나란히 보여야 하며(AC-005) 검색·필터가 항상 손 닿는 곳에 있어야 해서(FR-013), 한 화면에 가장 많은 카드를 담는 V-A의 고밀도 구성이 맞다. 분위기는 사용자가 말한 "전문적"이고, 색조가 없다는 피드백에 따라 색은 따뜻한 계열을 뚜렷하게 쓴다(`컬러/타이포그래피`). 어두운 판 전용이 아니라 두 판을 두는 것은 사용자의 선택이다 (FR-014)

### 레이아웃

- 패턴: 왼쪽 사이드바(208px) + 본문. 본문 위쪽에 막대(검색, 카드 만들기), 그 아래 정보 줄, 그 아래 본문 영역, 맨 아래 상태 줄
- 근거: V-A 시안 구성을 따른다. 칸 폭은 할 일 1 : 진행 중 1.1 : 완료 1의 비율(1280px 창에서 328 / 360 / 328)로 진행 중 칸을 조금 넓혀 시선 위계 2순위를 만든다
- 와이어프레임의 앱 이름 `스케줄 칸반보드`는 임시 문구다 (앱 이름은 `05-architecture.md` 결정 필요 3). 와이어프레임 안의 주석 문구(`맞는 카드가 없습니다` 등)도 참고일 뿐이고, 화면 문구는 이 문서의 `상태별 화면`이 우선한다 (예: 보관함 결과 없음은 `조건에 맞는 보관한 카드가 없습니다.`)

### 디자인 시스템

- 선택: 커스텀 (위 `기술 스택 연계`). CSS 변수로 두 판의 토큰을 정의하고 `<html data-theme="dark|light">`로 바꾼다. `color-scheme`도 함께 바꿔 스크롤바와 입력 칸의 브라우저 기본 모양이 판을 따르게 한다
- 덮어쓸 기본값: 해당 없음. 처음부터 시안의 모서리(4px)와 따뜻한 색 토큰으로 만든다
- 판을 처음 그리기 전에 적용한다. 저장된 판을 창을 띄우기 전에 읽어 창 바탕색과 `data-theme`를 맞춰 첫 화면 색이 번쩍이지 않게 한다. 저장된 선택이 없으면 밝은 판(창 바탕 #FAF3EE)이고, 어두운 판을 골라 저장한 사용자에게는 어두운 바탕(#1F1814)으로 연다. 창 바탕색과 첫 화면의 판이 다르면 번쩍이므로 둘은 항상 같은 판 값을 쓴다 (구현은 아키텍처 설계가 정한다)

### 인터랙션 패턴

| 패턴 | 적용 화면 | 구현 방식 |

| 판 전환 | 모든 화면 | 사이드바 라디오 두 개. 전환은 즉시(애니메이션 없음) |

### 컬러/타이포그래피

- 색 논리: **따뜻한 유사색 계조 + 칸별 상태 색 + 차가운 붉은색 하나(마감 지남)**. 바탕·카드·선·글자는 모두 색상각 약 20~30도(갈색·테라코타 쪽)의 낮은 채도 값이라 회색이 없다. 포인트(accent)는 테라코타·번트 오렌지, 칸 색은 호박 금색, 같은 테라코타, 이끼 연두색이다
- 포인트 색(`accent`): 어두운 판 #EC8148, 밝은 판 #B54A12. 쓰는 곳: 주요 버튼(`카드 만들기`, `저장`, `오늘로 이동`, `삭제 확인`), 사이드바 선택 항목과 선택된 라디오, 분할 버튼의 선택 칸, 오늘 표시, 진행 중 칸. 앱 이름과 포인트 색 글자는 `accent-text`
- 칸 색(`status-*`): **할 일 = 호박 금색**(#EBC85B / #9C6F00), **진행 중 = 테라코타**(포인트와 같은 값), **완료 = 이끼 연두**(#8DB36B / #4F7A2A). 칸 제목 글자와 칸 머리 아래 선(할 일·완료 2px, 진행 중 3px), 카드 바탕(각 칸 색을 아주 옅게 깐 `card-*`)과 카드 테두리 1px, 카드의 종류 아이콘, 캘린더 칩의 바탕·테두리·아이콘, 진행 기록의 상태 칩에 쓴다. 보드에서는 칸 이름 글자(`할 일`, `진행 중`, `완료`)가 항상 함께 있어 색만으로 상태를 알리지 않는다. 캘린더·보관함에서의 상태 색은 `NFR-004를 두 판에서 만족하는 방법` 표에 따른다
- 카드 좌측 막대는 쓰지 않는다. `anti-slop.md`가 "카드 한쪽에 두꺼운 색 띠"를 금지하고, 마감 지남도 같은 자리(테두리)를 쓰므로 막대가 있으면 둘이 섞인다. 대신 카드 바탕 전체의 색조, 칸 색 테두리, 칸 색 아이콘으로 상태가 보인다
- 마감 지남 색(`overdue`): 어두운 판 #F0457A, 밝은 판 #C0134F (라즈베리 레드). **앰버에서 바꾼 이유**: 포인트가 테라코타(주황)가 되었고 칸 색에 호박 금색이 생겨 앰버(노랑·주황)는 포인트·칸 색과 같은 색상 계열이 되어 구분되지 않는다. CIEDE2000 색차(25 안팎 이상이면 나란히 놓았을 때 구분)로 확인했다: 앰버 #F0B429는 할 일 호박 금색 #EBC85B와 7.7이라 사실상 같은 색이었고 새 포인트 #EC8148과도 23.1로 가까웠다. 새 붉은색은 포인트와 28.8(어두운 판) / 25.0(밝은 판), 호박 금색과 54.8 / 43.6, 이끼 연두와 63.7 / 64.0이다. 모양으로도 구분한다: 마감 지남은 카드 전체 2px 붉은 테두리 + 붉은 기가 도는 바탕(`overdue-soft`) + 삼각형 아이콘 + `N일 지남` 글자이고, 포인트는 면 채움(버튼)이나 1px 선택 테두리(사이드바)다. 이 붉은색은 `마감 지남`에만 쓴다 (오류 표시에는 쓰지 않는다. `결정 필요` 8)
- 주요 버튼: 어두운 판은 `accent` 면 + 어두운 글자(#1F1814), 밝은 판은 `accent` 면 + 흰 글자. 무채색 반전이 아니다
- 다크모드: 처음 열리는 기본은 밝은 판(살구빛 흰색), 어두운 판(따뜻한 갈색빛 차콜)을 전환 (`디자인 토큰`에 두 벌). 밝은 판은 같은 색상각의 옅은 살구빛 흰색이다. 와이어프레임은 어두운 판으로 그린 것이다
- 폰트: SUIT Variable 하나. 제목과 본문의 위계는 굵기(700 대 400~600)와 크기로 만든다

**anti-slop 대조 (색)**:

| 규칙 | 이 팔레트에서 |
|------|--------------|
| 보라-파랑 그라데이션, 어두운 배경 위 밝은 청록 | 없다. 그라데이션을 쓰지 않는다. 푸른 계열은 쓰지 않는다 |
| 네온 테두리·글로 | 붉은색은 선·면에만 쓰고 번짐·그림자·글로가 없다. 어두운 판에서 밝은 붉은 글자(#FF8DA6)는 글자에만 쓰고, 면과 선은 #F0457A다 |
| 크림·베이지를 고민 없이 기본으로 | 밝은 판의 #FAF3EE는 "무난한 크림"을 고른 것이 아니라 포인트 색(색상각 약 20도)을 같은 색상각에서 채도를 낮춘 값이다. 근거: 테라코타 포인트 아래에 차가운 회색 바탕을 두면 따뜻한 포인트가 탁해 보여 사용자가 바란 따뜻한 분위기가 약해진다. 베이지 한 색으로 끝나지 않게 사이드바(#F0E1D7), 칸별 카드 바탕(금색·살구·연두 각각), 오늘 칸을 서로 다른 옅은 색으로 구분한다. 어두운 판은 베이지가 아니라 갈색빛 차콜(#1F1814)이다 |
| 색 배경 위 회색 글자 | 글자색(`text`, `text-sub`, `text-mute`)이 모두 갈색 쪽으로 기운 따뜻한 색이라 칸별 색 카드 위에서도 회색으로 뜨지 않는다. 포인트·붉은색 면 위 글자는 `accent-on`·`overdue-on`(대비 4.9:1 이상) |

### 접근성

- 기준: WCAG 2.1 AA (본문 4.5:1, 컨트롤 테두리·아이콘 3:1)
- 필수 항목: 색만으로 구분하지 않는다 (NFR-004). 종류는 아이콘 + 글자, 마감 지남은 삼각형 아이콘 + `N일 지남` 글자 + 테두리. 상태(할 일·진행 중·완료)의 색은 칸 이름 글자가 항상 함께 있는 보드에서 쓰고, 캘린더 칩의 상태 색은 보조 표시다(아래 표). 오류는 아이콘 + 문구. 키보드 전용 조작을 요구로 확정하지는 않는다 (CAND-010). 움직임 줄이기 설정을 따른다(모든 전환 0ms)
- 마감일 날짜 선택 칸의 달력 아이콘(`::-webkit-calendar-picker-indicator`)은 브라우저가 `color-scheme`에 따라 밝게 또는 어둡게 그리므로, `color-scheme`을 판에 맞춰(어두운 판 dark, 밝은 판 light) 두 판 모두에서 아이콘이 입력 칸 바탕 위에서 보이게 한다. 브라우저가 그리는 아이콘이라 이 문서가 대비 수치를 계산하지 못했고, 구현에서 두 판 모두 눈으로 확인한다
- 끌기가 필요한 동작에는 끌지 않는 방법이 있다(WCAG 2.5.7): 보드의 `⋯` 메뉴, 캘린더는 카드 입력 화면의 마감일 칸. 끌기 중의 놓을 수 있는 칸 표시는 색 외에 점선 윤곽도 쓴다

## 공통 구성 (SCR-001, SCR-003, SCR-004의 사이드바와 막대)

```
┌────────────┬────────────────────────────────────────────┐
│ 앱 이름     │ 상단 막대 (화면마다 다름)                     │
│ 보드  15    ├────────────────────────────────────────────┤
│ 캘린더      │ 본문                                        │
│ 보관함  3   │                                            │
│            │                                            │
│ 종류 (필터) │                                            │
│ 우선순위    │                                            │
│            │                                            │
│ 화면 밝기   │                                            │
│ 저장 상태   ├────────────────────────────────────────────┤
│            │ 하단 줄 (건수)                               │
└────────────┴────────────────────────────────────────────┘
```

- **사이드바 (208px, `bg-side`)**: 앱 이름(16px 굵게, `accent-text` 색) → 이동 3항목(보드, 캘린더, 보관함. 현재 화면은 `accent-soft` 바탕과 1px `accent` 테두리와 굵은 글자. 이동 항목의 건수 글자는 `text-mute`) → 필터(보드·보관함에서만) → 화면 밝기 → 저장 상태
- **이동 항목의 숫자**: 보드는 보관하지 않은 카드 전체 수, 보관함은 보관한 카드 수. 필터와 검색의 영향을 받지 않는다
- **필터 (종류, 우선순위)**: 행마다 라디오 원 + 이름 + 해당 카드 수. 두 목록 모두 맨 위에 `전체` 항목이 있다. 종류 목록은 `전체`, `개발 버그`, `할 일`, 우선순위 목록은 `전체`, `낮음`, `중간`, `높음` 순서다(우선순위 `없음`은 목록에 없다). 처음 열었을 때와 조건이 없을 때 두 목록 모두 `전체`가 선택되어 있다(조건 없음). 한 목록에서는 항목 하나만 선택되는 라디오 방식이고, **선택된 항목을 다시 눌러도 해제되지 않는다** (해제하는 동작은 없다. `전체`를 고르면 그 목록의 조건이 지워진다). 종류와 우선순위는 서로 AND로 결합한다 (AC-027, AC-047). `전체`의 숫자는 지금 화면 대상(보드는 보관하지 않은 카드, 보관함은 보관한 카드) 전체의 값이고, 나머지 항목의 숫자도 같은 범위의 값이다. 우선순위가 없는 카드는 우선순위 `전체`에는 세어지지만 `낮음`·`중간`·`높음`을 고르면 나오지 않아, 세 항목의 숫자 합이 `전체`보다 작을 수 있다
- **필터 행의 상태**:

| 상태 | 모양 |
|------|------|
| 기본 | 라디오 원(`control` 테두리 1px) + 이름(`text-sub`) + 건수(`text-mute`). 높이 34 |
| 호버 | 별도 모양 변화 없이 포인터 커서만 바뀐다. 키보드 포커스는 `focus` 링 |
| 선택 | 라디오 원이 `accent` 테두리 + 안쪽 점, 이름이 `text` 색 굵은 글자. 항목 바탕은 바뀌지 않는다. 목록마다 정확히 하나가 이 상태다(처음은 `전체`) |
| 비활성 | 읽기 실패 때 두 목록 전체가 눌리지 않는다. 라디오 원 테두리는 `disabled`. 선택은 마지막 값(처음이면 `전체`)으로 그대로 보인다 |

- **화면 밝기**: 라벨 `화면 밝기` 아래 라디오 두 행(고른 행은 `accent` 색 테두리와 안쪽 점) `어두운 판`(달 아이콘), `밝은 판`(해 아이콘). 선택 즉시 모든 화면이 바뀌고 설정에 저장한다 (AC-037, AC-038). 첫 실행(저장된 선택이 없을 때)은 밝은 판이고, 이미 저장된 선택은 그대로 따른다 (ASM-017)
- **저장 상태 (맨 아래)**: `내 PC에 저장됨`(체크 원 아이콘), 저장 중에는 `저장 중`(글자만), 실패하면 `저장하지 못함`(오류 아이콘, 굵은 글자). 읽기 실패 때는 `읽지 못함`. 반복 애니메이션 없음
- **저장 실패 알림 줄**: 사이드바 밖 본문 맨 위(막대 아래)에 `role="alert"` 줄이 붙는다. 칸 이동·보관·삭제와 캘린더에서 끌어 마감일을 바꾸는 일이 실패했을 때 문구는 `저장하지 못했습니다. 카드는 바뀌지 않았습니다.`와 `다시 저장` 버튼(실패한 요청을 그대로 다시 보낸다). 밝기 전환이 실패했을 때 문구는 `저장하지 못했습니다. 화면의 내용은 그대로 남아 있습니다.`와 `다시 저장` 버튼. 저장이 성공하면 사라진다. 대화상자 안에서 난 실패는 대화상자 안 알림이 맡는다
- **예상하지 못한 오류 알림**: 저장소가 예상하지 못한 오류(`INTERNAL`)를 돌려주면 같은 알림 줄 자리에 일반 문구 `예상하지 못한 오류가 났습니다. 데이터는 바뀌지 않았습니다.`와 접힌 `자세히`(펼치면 오류의 진단 문장 `message`를 흐린 색 한 줄로 보인다)가 붙는다. 다시 시도 버튼은 없다. 같은 진단 문장이 main의 콘솔 로그에도 남는다 (로그 파일은 만들지 않는다). 화면을 그리다 난 오류는 앱 전체를 대체하는 안내(`화면을 그리지 못했습니다. 앱을 닫고 다시 여세요. 저장된 데이터는 바뀌지 않았습니다.`와 접힌 `자세히`)가 맡는다
- **하단 줄 (36px, `bg-side`)**: 화면별 건수 문구
- **상단 막대와 하단 줄의 소유자**: `AppShell`이 `TopBar`와 하단 줄(건수 줄)을 소유한다. `BoardScreen`, `CalendarScreen`, `ArchiveScreen`은 상단 막대와 하단 줄을 그리지 않고 막대와 하단 줄 사이의 본문만 그린다. 캘린더의 기간 이동(`PeriodNav`)과 `월 | 주` 분할 버튼은 `AppShell`이 `TopBar`의 children으로 넣는다. 하단 줄 내용은 `AppShell`이 현재 화면에 따라 정한다: 보드 `카드 N건 · 보관함 N건`, 캘린더 `N월에 마감인 카드 N건`, 보관함 `보관함 N건`. 저장 상태는 하단 줄이 아니라 사이드바 맨 아래에 있다. 아래 화면별 `상단 막대`·`하단 줄` 항목은 `AppShell`이 `TopBar`와 하단 줄로 그리는 모양이다.

**컴포넌트 구성**:
- 상단 막대(높이 56, `TopBar`): 검색 입력(폭 380, `검색` 라벨이 입력 칸 안 왼쪽에 항상 보이고 안내 문구는 `제목에 포함된 글자`, 글자가 있으면 오른쪽에 지우기 ×), 오른쪽 끝 `카드 만들기` 주요 버튼(+ 아이콘, 폭 140)
- 정보 줄(높이 44): 왼쪽 `오늘 11월 3일 화요일`(14px 보조), 오른쪽 `마감 지난 카드 N건` 요약 칩(`overdue` 면 + `overdue-on` 글자, 삼각형 아이콘, N이 0이면 칩이 없다). 요약 칩은 표시 전용이고 누르는 요소가 아니다
- 조건 줄(조건이 있을 때만 정보 줄 아래에 28px 추가): `검색: 세금 ×`, `종류: 개발 버그 ×`, `우선순위: 높음 ×` 칩과 `조건 모두 지우기` 텍스트 버튼, 오른쪽에 `결과 7건 / 전체 15건`. 사이드바에서 `전체`를 고른 목록은 조건이 아니므로 조건 칩으로 나타나지 않는다(`종류: 전체` 같은 칩이 없다). 조건 칩의 ×나 `조건 모두 지우기`를 누르면 해당 목록의 사이드바 선택이 `전체`로 돌아간다. `aria-live="polite"`로 결과 건수를 알린다
- 칸 3개: 칸 머리(`할 일` 16px 굵게 + 건수 14px 흐린 색, 조건이 있으면 `2 / 6` 모양 건수) + 머리 아래 선(칸 색: 할 일 `status-todo` 2px, 진행 중 `status-doing` 3px, 완료 `status-done` 2px). 칸 제목 글자도 그 칸 색(글자용 값) + 카드 목록. 칸 머리는 고정되고 카드 목록만 세로 스크롤한다 (UC-003 Alt Flow 2: 칸에 다 들어가지 않을 때의 설계는 `칸별 스크롤`)
- 카드(높이 62, 폭은 칸 폭, 모서리 4px, 바탕 `card-todo`/`card-doing`/`card-done`, 1px `status-*-line` 테두리): 아래 `카드 구조` 참고
- 하단 줄(`AppShell`이 그린다): `카드 15건 · 보관함 3건`

**카드 구조** (한 겹 카드, 카드 안에 카드 없음):

| 위치 | 내용 | 비고 |
|------|------|------|
| 1줄 왼쪽 | 종류 아이콘(14px) + 제목(14px 굵기 600, 한 줄, 길면 `…`) | 전체 제목은 `title` 속성과 SCR-002에서 본다 |
| 1줄 오른쪽 끝 | `⋯` 상태 이동 버튼(24x22, `control` 테두리) | 카드 열기와 별개로 눌린다 |
| 2줄 왼쪽 | 종류 칩(`개발 버그`: 채움, `할 일`: 테두리, 12px 굵게) + 마감 글자 | 마감: `마감 11/06`, 없으면 `마감 없음`(흐린 색), 해가 다르면 `마감 2027/01/05` |
| 2줄 오른쪽 | 우선순위: 막대 3개(채움 수 = 높음 3, 중간 2, 낮음 1) + 글자 `높음`/`중간`/`낮음` | 우선순위가 없으면 비운다 |
| 완료 카드 2줄 끝 | `보관` 보조 버튼(44x20, 12px 굵게) | 완료 카드에만. 제목과 보조 글자는 `text-sub`로 낮아지고 완료 색(`status-done`)의 종류 아이콘이 붙는다 |
| 마감 지남 카드 | 테두리 2px `overdue`, 바탕 `overdue-soft`, 마감 글자 자리가 삼각형 아이콘 + `11/01 · 2일 지남`(굵게, `overdue-text`) | 날짜 차 N은 오늘에서 마감일을 뺀 일수. 판정은 `마감일 < 오늘 AND 상태 ≠ 완료`, 당일은 지남이 아니다 (AC-024, AC-025, ASM-014) |

**인터랙션**:

| 트리거 | 액션 | 결과 |
|--------|------|------|
| `카드 만들기` 클릭 | SCR-002를 새 카드 모드로 연다 | 제목 입력에 포커스. 저장하면 닫히고 고른 상태의 칸에 새 카드가 나타난다: 상태를 고르지 않으면 할 일 칸 (AC-001), 진행 중으로 골랐으면 진행 중 칸 (AC-041) |
| 카드 클릭 | SCR-002를 상세 모드로 연다 | 닫으면 보드의 스크롤·조건이 그대로다 |
| 카드를 다른 칸으로 끌어다 놓기 | 상태를 그 칸의 값으로 바꾸는 요청을 보낸다 | 놓은 순간 카드는 원래 칸에 그대로 있고 사이드바가 `저장 중`이다. 저장이 성공하면 150ms로 새 칸에 자리 잡는다 (AC-003). 저장이 실패하면 카드는 원래 칸에 남고 저장 실패 알림이 뜬다. 같은 칸이나 칸 밖에 놓으면 아무 일도 없다. 드래그 중 대상 칸 윗선이 2px로 굵어진다. 놓는 위치는 무시하고 칸 안 순서는 정렬 규칙을 따른다 |
| `⋯` 클릭 | 메뉴가 열린다. 현재 상태를 뺀 두 항목 `진행 중으로 옮기기` 등 | 항목 선택 시 끌기와 같은 결과. Esc나 바깥 클릭으로 닫는다. 끌기의 대안이다 (WCAG 2.5.7) |
| 완료 카드의 `보관` 클릭 | 같은 자리가 `보관 확인` `취소` 두 버튼으로 바뀐다 | `보관 확인`을 누르면 요청을 보내고 사이드바가 `저장 중`이다. 저장이 성공하면 카드가 보드와 캘린더에서 사라지고 사이드바 보관함 숫자가 늘어난다 (AC-019). 저장이 실패하면 카드는 보드에 그대로 남고 저장 실패 알림이 뜬다. `취소`면 원래로 |
| 검색 입력 | 글자가 바뀔 때마다 제목에 그 글자가 든 카드만 보인다 | 대소문자 구분 없음 (AC-026, ASM-012) |
| 사이드바 종류·우선순위 행 클릭 | 그 목록의 선택 항목을 클릭한 행으로 바꾼다 (라디오) | 두 목록은 AND (AC-027). `전체`를 고르면 그 목록의 조건이 풀린다. 선택된 항목을 다시 눌러도 해제되지 않고 그대로다 (AC-047) |
| 조건 칩의 × / `조건 모두 지우기` | 그 조건/모두 해제 | 해당 목록의 사이드바 선택이 `전체`로 돌아가고 모든 카드가 다시 보인다 (AC-027, AC-047) |
| 사이드바 캘린더·보관함 클릭 | SCR-003·SCR-004로 이동 | 보드의 조건은 보드로 돌아오면 그대로 유지(앱이 켜져 있는 동안만, 저장하지 않는다) |
| 밝기 라디오 | 판 전환 | 즉시(낙관적). 저장 실패 시 이번 실행 동안은 바뀐 판으로 보이고 저장 실패 알림 줄이 뜬다 (UC-011 Alt Flow 1) |

| 에러: 저장 실패 | 상태 이동·보관의 저장이 실패하면 화면은 바뀌지 않은 채(카드가 원래 칸에 그대로) 알림 줄 `저장하지 못했습니다. 카드는 바뀌지 않았습니다.` + `다시 저장` 버튼(같은 요청을 다시 보낸다). 밝기 전환의 저장이 실패하면 화면은 바뀐 판으로 둔 채 알림 줄 `저장하지 못했습니다. 화면의 내용은 그대로 남아 있습니다.` + `다시 저장` 버튼. 사이드바 저장 상태가 `저장하지 못함` (AC-031) |
| 정상 | 칸마다 카드 목록. 칸 안 순서는 만든 순서의 최신이 위(임시 가정, `결정 필요` 1). 마감이 지난 카드가 있어도 순서를 바꾸지 않고 강조만 한다 |

- 1600px 이상에서는 칸 폭 최대 520px

### SCR-002: 카드 입력·상세

**관련 FR**: FR-001, FR-002, FR-004, FR-007, FR-008, FR-009, FR-010, FR-011 (와이어프레임: wireframes/SCR-002.svg)

**시선 위계**: 1) 제목 입력과 대화상자 제목(만들기인지 수정인지 보관된 카드인지) 2) 종류·상태·마감일 한 줄(상태와 마감이 카드의 핵심 속성이라 제목 바로 아래) 3) 진행 기록 목록(오른쪽 열, 시간순) 4) 설명·메모 5) 저장 버튼(오른쪽 아래 주요 버튼 하나, 삭제는 반대편 왼쪽 아래에 떼어 놓는다). 오류 문구가 뜨면 오류가 1순위가 된다

**레이아웃**:
```
┌──────────────────────────────────────────────────────────┐
│ 카드 상세   [벌레] 개발 버그                              [✕]  │

│ 오류 문구 줄                    │  ...                      │
│ 상세 설명 [textarea]            │                          │
│ 추가 메모 [textarea]            │ 기록 내용 [textarea]        │
```

대화상자 폭 880px, 높이 최대 `창 높이 - 48px`(기본 680px). 뒤 화면은 `scrim`으로 덮는다. 열린 경로(보드, 캘린더, 보관함)에 상관없이 같은 대화상자다.

**컴포넌트 구성**:
- 머리(높이 56): 제목 `카드 만들기` / `카드 상세` / `보관한 카드`(보기만 가능), 상세일 때 종류 아이콘과 글자, 오른쪽 `✕`(닫기)
- 왼쪽 열(폭 440): 입력 항목 (아래 표). 열 안쪽이 길어지면 이 열만 스크롤한다
- 오른쪽 열(폭 340): `진행 기록` 제목 + 건수, 기록 목록(스크롤), 기록 입력
- 바닥 줄(높이 64): 왼쪽 `삭제`(만들기 모드에서는 없음, 완료 카드면 그 옆에 `보관`), 오른쪽 `취소`, `저장`(주요)

**입력 항목**:

| 항목 | 필수 | 입력 방식 | 기본값 | 오류 문구 | 근거 |
|------|------|----------|--------|----------|------|
| 제목 | 필수 (라벨 옆 `필수`) | 한 줄 텍스트 | 없음 | `제목을 입력하세요`(칸 아래, 오류 아이콘 + 글자, 칸 테두리 2px) | AC-002, AC-035, ASM-006 |
| 종류 | 선택 | 분할 버튼 `개발 버그` / `할 일`(아이콘 + 글자) | 할 일 | - | AC-013, AC-014, ASM-007 |
| 상태 | 선택 | 선택 목록(콤보박스, 내장 `select`). **새 카드 모드**: `할 일`, `진행 중` 두 항목뿐(`완료` 없음). **상세(편집) 모드**: `할 일`, `진행 중`, `완료` 세 항목. 두 모드 모두 잠그지 않는다 | 새 카드는 `할 일`(처음 선택), 상세 모드는 현재 값 | - | AC-041, AC-042, AC-001, AC-004. 새 카드에서 `진행 중`을 고르고 저장하면 진행 중 칸에 나타난다. 상세에서 상태를 바꾸고 저장하면 칸이 옮겨진다 (AC-003). `보관`은 상태 값이 아니다 |
| 마감일 | 선택 | 날짜 선택 칸(브라우저 기본 `input type="date"`). 칸 오른쪽 달력 아이콘으로 달력을 열어 날짜를 고르고, 칸에 직접 입력해도 된다. 외부 날짜 라이브러리 없음 (NFR-001). 값 형식 `YYYY-MM-DD`, 칸 안의 날짜를 지우면 마감 없음(비우기 가능). 라벨은 `마감일`(형식 설명을 라벨에 붙이지 않는다) | 비어 있음 | `존재하지 않는 날짜입니다. 2026-11-06 형식으로 입력하세요` (AC-029는 도메인 검증이 그대로 한다. 날짜 선택 칸은 없는 날짜를 값으로 내지 않으므로 이 문구는 그런 값이 들어온 경우에만 보인다, `결정 필요` 13) | AC-007, AC-008, AC-029, AC-043 |
| 우선순위 | 선택 | 분할 버튼 `없음` / `낮음` / `중간` / `높음` (화면 순서) | 없음 | - | AC-016, ASM-008 |
| 상세 설명 | 선택 | 여러 줄 텍스트 | 비어 있음 | - | AC-015 |

필수는 제목 하나다. 모든 입력에 라벨이 항상 보인다(입력 안내 문구만 두지 않는다).

**상태 칸 (새 카드 모드)**: 잠기지 않은 보통 콤보박스다. 열면 `할 일`(처음 선택), `진행 중` 두 항목만 있고 `완료`는 없다(와이어프레임 SCR-002 오른쪽 위 점선 상자). 상세 모드의 목록은 세 항목이다. 보관한 카드(읽기 전용)는 변경 없이 마지막 상태 `완료`를 글자로 보인다.

**마감일 칸**: 오른쪽 달력 아이콘(`::-webkit-calendar-picker-indicator`)이 입력 칸 안에 있다. 칸에 보이는 날짜 모양은 브라우저가 로케일에 맞춰 정하고(한국어에서는 `2026. 11. 06.` 꼴로 추정, 확인하지 못함) 카드에 저장되는 값은 `YYYY-MM-DD`다. 아이콘이 두 판에서 보이는 것은 `color-scheme`을 판에 맞추는 것으로 보장한다(`접근성`).

**진행 기록**:
- 목록은 남긴 순서대로 위에서 아래로 쌓인다. 새 기록은 맨 아래에 붙고 목록이 그 위치로 스크롤된다 (AC-017). 다른 카드의 기록은 나오지 않는다
- 기록 한 건: `11/01 10:20`(남긴 때, 14px 흐린 색) + 상태 칩(`할 일` / `진행 중` / `완료`, 12px 굵게, 그 기록을 남긴 때의 카드 상태) + 내용(14px, 줄바꿈) (AC-018). 해가 다르면 `2025/12/30 10:20`
- 입력: `기록 내용` 라벨 + 여러 줄 입력 + 왼쪽 `기록에 붙는 상태: 진행 중`(저장된 카드 상태를 보여 준다. 위 입력 항목에서 상태를 고쳤어도 `저장`을 누르기 전에는 이 값이 바뀌지 않는다) + `기록 추가` 버튼
- 내용이 비었거나 공백뿐이면 `기록 추가` 버튼은 눌리지 않는다 (UC-006 Alt Flow 1)
- 누르면 그 자리에서 바로 저장한다(위 카드 입력 항목의 `저장`과 별개). 실패하면 입력은 남고 입력 아래에 `기록을 저장하지 못했습니다`(오류 아이콘 + 글자)와 `다시 저장`
- 기록의 수정·삭제는 만들지 않는다 (CAND-009)
- 만들기 모드에서는 오른쪽 열에 `카드를 저장한 뒤 기록을 남길 수 있습니다`만 보인다 (UC-006 선행 조건: 카드가 있다)

| 마감일 칸의 달력 아이콘 클릭 | 달력을 연다 | 날짜를 고르면 그 날짜가 마감일 칸에 들어간다 (AC-043). 칸에 직접 입력해도 같다 |
| `저장` | 검증 후 저장 | 제목이 비면 저장하지 않고 제목 칸 아래 오류와 첫 오류 칸으로 포커스 (AC-002, AC-035). 마감일이 없는 날짜면 저장하지 않고 마감일 칸 아래 오류 (AC-029). 통과하면 저장하고 닫으며, 보드·캘린더에 고친 내용이 보인다 (AC-022). 만들기 모드는 고른 상태의 칸(기본 할 일)에 나타난다 (AC-001, AC-041) |

| 캘린더·보관함에서 연 대화상자를 닫음 | 연 화면으로 돌아간다 | 보기 위치가 그대로다 |

**보관한 카드 모드 (보기 전용, ASM-015)**: 머리 제목이 `보관한 카드`, 입력 칸 대신 읽기 전용 글자로 값을 보인다(제목, 종류, 마감일, 우선순위, 상세 설명, 추가 메모, 마지막 상태 `완료`, 보관한 날). 진행 기록 목록은 보이지만 기록 입력은 없다. 바닥 줄에는 `닫기`와 `삭제`만 있다(`저장`, `보관 해제` 없음, CAND-003). 삭제는 같은 삭제 확인 줄을 쓴다 (AC-040: 보관한 카드도 확인 단계 뒤 삭제할 수 있고 진행 기록이 함께 삭제된다. 사용자가 정했다). 수정과 기록 추가는 할 수 없다 (ASM-015).

### SCR-003: 캘린더

**관련 FR**: FR-004, FR-005 (와이어프레임: wireframes/SCR-003.svg, 월 보기)

**시선 위계**: 1) 마감 지난 칩(붉은 테두리, `overdue-soft` 바탕, 삼각형 아이콘) 2) 오늘 표시(날짜 숫자가 포인트 색 알약, 그 날짜 칸 바탕 `bg-today`) 3) 기간 제목(20px 굵게)과 날짜 칸의 카드 칩 4) 날짜 숫자와 범례. 격자 선은 구획용이고 시선을 끌지 않게 `line` 색으로 둔다. 칩을 끄는 동안에는 놓을 수 있는 날짜 칸의 점선 윤곽이 1순위가 된다

**레이아웃**:
```
┌────────────┬────────────────────────────────────────────┐
│ 사이드바    │ [‹ 보드로 돌아가기] 2026년 11월  [월|주] [‹][›] [오늘로 이동]│
│ (필터 없음) ├────────────────────────────────────────────┤
│            │ 일  월  화  수  목  금  토                     │
│            │ ┌──┬──┬──┬──┬──┬──┬──┐                     │
│            │ │1 │2 │3오늘│..                              │
│            │ │칩│칩│칩 │   (칩을 끌어 다른 칸에 놓으면 마감일 변경)│
│            │ └──┴──┴──┴──┴──┴──┴──┘                     │
│            │ 범례(아이콘+글자)            마감일 없는 카드 3건…  │
├────────────┴────────────────────────────────────────────┤
│ 하단 줄: 11월에 마감인 카드 11건                              │
└─────────────────────────────────────────────────────────┘
```

**컴포넌트 구성**:
- 상단 막대(높이 56, `TopBar`. 기간 이동과 `월 | 주` 분할 버튼은 `AppShell`이 `TopBar`의 children으로 넣고 하단 줄 `N월에 마감인 카드 N건`도 `AppShell`이 그린다): 왼쪽 `보드로 돌아가기` 버튼(왼쪽 화살표 + 글자, SCR-001로 이동), 기간 제목(월 보기 `2026년 11월`, 주 보기 `2026년 11월 1일 ~ 7일`), 오른쪽 `월 | 주` 분할 버튼(선택 칸은 `accent-soft` 바탕 + `accent` 테두리 + 굵은 글자), `‹` `›` 이전/다음 기간, `오늘로 이동`(주요 버튼)
- 요일 줄(일요일 시작): `일 월 화 수 목 금 토`(14px 굵게 흐린 색)
- 날짜 칸: 월 보기는 7열 x 4~6행, 칸 높이 최소 124px. 칩 3개와 `+N건 더 보기`가 함께 나오는 칸이 있는 주는 133px이다(계산은 아래 `월 보기 높이 계산`). 창이 높으면 늘어난다. 날짜 숫자(14px) + 카드 칩 세로 목록. 이 달이 아닌 날은 `bg-side` 바탕이고 카드가 없지만 칩을 놓을 수는 있다(아래 인터랙션)
- 달력 칩(높이 22, 모서리 3px, 제목 13px): 카드 상태의 색을 입힌다. 바탕 `card-todo`/`card-doing`/`card-done`, 1px `status-*-line` 테두리, 종류 아이콘은 상태 색(`status-*`), 제목은 `text`(완료는 `text-mute`) + (완료면 끝에 원 안 체크, `status-done` 색). 마감 지난 칩은 `overdue-soft` 바탕, 1px `overdue` 테두리, 삼각형 아이콘, 굵은 `overdue-text` 제목(상태 색보다 우선). 칩 전체가 누르는 영역이자 끄는 대상이다(`draggable`). 월 보기 칩에는 상태 글자가 없으므로 `aria-label`과 `title`에 `진행 중, 마감 11/12 …`처럼 상태를 적고, 주 보기 칩과 `+N건 더 보기` 팝업 칩은 끝에 상태 글자 칩(12px 굵게, 상태 색 테두리·글자)을 붙인다. 월 보기 칩의 색 차이(할 일 금색, 진행 중 테라코타)는 보조다
- `+N건 더 보기`: 월 보기에서 한 날짜 칸에 칩을 3개까지 보이고 나머지가 있으면 칸 아래에 12px 굵은 글자로 둔다. 누르면 그 날짜의 카드 전체를 14px 칩 목록으로 보이는 팝업(최대 높이 320px, 스크롤)이 칸 옆에 열린다. 모든 카드에 닿을 수 있다 (UC-004 Alt Flow 3). **팝업(`DayPopover`) 안의 칩은 끌 수 없다.** 팝업 안에서는 끌기를 지원하지 않고, 그 카드의 마감일은 칩을 눌러 연 카드 입력 화면에서 바꾼다
- 범례(아이콘 + 글자): 개발 버그, 할 일, 마감 지남, 완료. 오른쪽에 `마감일이 없는 카드 3건은 보드에서만 보입니다`(마감일 없는 카드 수 N)

**월/주 보기**:

| 보기 | 구성 | 카드가 많을 때 |
|------|------|---------------|
| 월 (기본) | 한 달 격자. 칸당 칩 3개까지 | `+N건 더 보기` 팝업 |
| 주 | 7열 한 줄. 날짜 칸이 세로로 길고, 칩 제목을 14px로 두 줄까지 줄바꿈해 전체를 보인다 | 칸 안에서 세로 스크롤. 더 보기 없음 |

월/주 선택, 보고 있는 기간은 앱이 켜져 있는 동안만 기억한다(저장하지 않는다). 앱을 열면 월 보기, 오늘이 든 달이다 (설계 가정, `결정 필요` 10).

|--------|------|------|
| 칩 클릭 | SCR-002를 상세 모드로 연다 | 닫으면 같은 기간·보기로 돌아온다 (AC-030). 움직임 없이 누르면 열리고, 끌기와 겹치지 않는다(브라우저 기본 동작) |
| 칩을 끌어 다른 날짜 칸에 놓기 (월·주 보기 모두) | 그 카드의 마감일을 놓은 날짜로 바꾸는 요청을 보낸다. 바뀌는 것은 마감일뿐이고 상태와 다른 내용은 그대로다 (AC-044, ASM-018) | 끄는 중: 끌리는 칩은 투명도 50%로 흐려지고, 포인터가 놓을 수 있는 날짜 칸(원래 칸이 아닌 칸) 위에 있으면 그 칸이 2px 점선 윤곽(`accent`)과 옅은 바탕(`accent-soft`)으로 강조된다(보드의 칸 강조와 같은 방식이고, 색 외에 점선 윤곽도 쓴다). 놓은 순간 칩은 원래 칸에 그대로 있고 사이드바가 `저장 중`이다. 저장이 성공하면 칩이 새 칸으로 옮겨 간다(150ms, 낙관적 반영 없음). 하단 줄의 `N월에 마감인 카드 N건`도 그때 다시 센다 |
| 칩을 같은 칸이나 칸 밖에 놓기 | 아무것도 하지 않는다 | 칩은 그대로이고 저장 요청도 없다 (AC-045). 칸 밖은 격자 밖(요일 줄, 범례, 사이드바, 막대 등)이다 |
| 칩을 이 달이 아닌 날의 칸에 놓기 | 놓은 날짜로 마감일이 바뀐다 | 이전/다음 달에서 넘어온 칸(`bg-side` 바탕)도 놓을 수 있다. 다만 그 칸은 카드를 그리지 않는 칸이라 저장이 성공하면 칩이 이 달 보기에서 사라져 보인다(이전/다음 달로 이동하면 보인다, `결정 필요` 14) |
| 끌어다 놓은 변경의 저장 실패 | 칩은 원래 칸에 그대로, 마감일도 그대로 | 막대 아래 알림 줄 `저장하지 못했습니다. 카드는 바뀌지 않았습니다.` + `다시 저장`(같은 요청을 다시 보낸다). 사이드바 저장 상태는 `저장하지 못함` (AC-046, AC-031과 같은 방식) |
| 완료 카드·마감 지난 카드의 칩 끌기 | 일반 칩과 같다 | 완료 카드도 끌 수 있다 (ASM-018). 마감일을 오늘 이후로 옮기면 마감 지남 표시는 그때 다시 계산한다. 보관한 카드는 캘린더에 없다 (AC-019) |
| `+N건 더 보기` 클릭 | 날짜 팝업 | 팝업 안 항목을 누르면 SCR-002가 열린다. Esc나 바깥 클릭으로 닫는다. 팝업 안의 칩은 끌 수 없다 |
| 키보드로 마감일 바꾸기 | 칩을 열어(Enter) 카드 입력 화면의 마감일 칸에서 고친다 | 끌기의 키보드·끌지 않는 대안이다 (WCAG 2.5.7) |
| `‹` / `›` | 월 보기는 한 달, 주 보기는 한 주 이동 | 기간 제목이 바뀐다 |
| `오늘로 이동` | 오늘이 든 달(주)로 | 오늘 날짜 숫자가 알약 모양으로 보인다 |
| `월` / `주` 분할 버튼 | 보기를 바꾼다 | 보고 있던 날짜가 속한 기간을 유지한다 |
| `보드로 돌아가기` 또는 사이드바 `보드` | SCR-001로 이동 | 같은 결과 |

**상태별 화면**:

| 상태 | 표시 내용 |
|------|----------|
| 로딩 | 읽는 동안 격자 뼈대만 보이고 칩은 없다 (200ms 이내) |
| 빈값 | 마감일이 있는 카드가 없으면 빈 격자 + 격자 위에 `마감일이 있는 카드가 없습니다. 카드에 마감일을 적으면 이 달력에 나타납니다.` 한 줄. 오류 없이 열린다 (UC-004 Alt Flow 2) |
| 에러 | 읽기 실패 때는 SCR-001의 읽기 실패 패널을 이 화면 본문에도 같은 문구로 쓴다 (이동 자체가 막힌다). 저장 실패 알림 줄은 SCR-001과 같다. 끌어서 바꾼 마감일의 저장이 실패한 경우는 위 인터랙션 표 |
| 정상 | 마감일이 있는 카드가 그 날짜 칸에 보인다 (AC-009). 마감일 없는 카드는 나오지 않는다 (AC-010). 보관한 카드는 나오지 않는다 (AC-019). 완료 카드는 보이되 제목이 흐리고 원 안 체크가 붙는다(CAND-007 임시 가정, `결정 필요` 6). 마감 지난 카드는 붉은 칩. 모든 칩은 끌 수 있다(팝업 안 칩 제외) |

이 화면에는 검색·필터가 없다. 사이드바의 필터 영역을 이 화면에서는 숨기고, 보드에서 건 조건은 이 화면에 영향을 주지 않는다 (`결정 필요` 7).

### SCR-004: 보관함

**관련 FR**: FR-010, FR-011, FR-013 (와이어프레임: wireframes/SCR-004.svg)

**시선 위계**: 1) 보관한 카드의 제목(14px 굵게) 2) 검색 입력과 적용 중인 조건 3) 종류·마감·우선순위·보관한 날(14px 보조 색). 이 화면은 읽는 화면이라 붉은색(마감 지남)을 쓰지 않는다. 보관한 카드는 모두 완료라서 행의 종류 아이콘만 완료 색(`status-done`)이다. 보관 카드는 완료라서 마감 지남 판정 대상이 아니다 (AC-025)

**레이아웃**:
```
┌────────────┬────────────────────────────────────────────┐
│ 사이드바    │ [‹ 보드로 돌아가기] 보관함        [검색 ______]   │
│ (필터 있음) ├────────────────────────────────────────────┤
│            │ 보관한 카드 3건 · 보기만 할 수 있습니다           │
│            │ 제목        종류   마감   우선순위  보관한 날       │
│            │ ───────────────────────────────────────    │
│            │ [아이콘] 제목  [칩]  마감 10/30 중간  11/01 [삭제] [>] │
│            │ ...                                         │
├────────────┴────────────────────────────────────────────┤
│ 하단 줄: 보관함 3건                                          │
└─────────────────────────────────────────────────────────┘
```

**컴포넌트 구성**:
- 상단 막대(높이 56, `TopBar`): `보드로 돌아가기` 버튼, 화면 제목 `보관함`(20px 굵게), 오른쪽 끝 검색 입력(SCR-001과 같은 모양)
- 정보 줄: `보관한 카드 3건 · 보기만 할 수 있습니다`. 조건이 있으면 SCR-001과 같은 조건 칩 줄과 `결과 N건 / 전체 N건`. 사이드바에서 `전체`를 고른 목록은 조건 칩으로 나타나지 않는다
- 목록: 열 머리(`제목`, `종류`, `마감`, `우선순위`, `보관한 날`, 12px 굵게 흐린 색, 정렬 기능 없음) + 행(높이 44, 1px `line` 구분). 행: 종류 아이콘 + 제목 / 종류 칩 / `마감 10/30`(없으면 `마감 없음`) / 우선순위(막대 + 글자 `낮음`·`중간`·`높음`) / 보관한 날 `11/01` / `삭제` 보조 버튼(60x24, 12px 굵게, `control` 테두리, 글자 `text-sub`) / 오른쪽 끝 `›`. `삭제` 버튼은 행 열기와 별개로 눌린다
- 필터: 사이드바의 종류·우선순위(SCR-001과 같은 동작과 `전체` 항목, 숫자는 보관한 카드 기준. `전체`의 숫자는 보관한 카드 전체 수). 보관함의 선택은 보드와 따로 기억한다
- 하단 줄(`AppShell`이 그린다): `보관함 3건`
- 정렬: 보관한 날이 최신인 것이 위 (임시 가정, `결정 필요` 1)

**인터랙션**:

| 트리거 | 액션 | 결과 |
|--------|------|------|
| 행 클릭(`삭제` 버튼 밖) | SCR-002를 보기 전용 모드로 연다 | 보관한 카드의 내용이 보인다 (AC-020). 수정, 기록 추가, 보관 해제 없음 (ASM-015). 바닥 줄의 `삭제`로도 지울 수 있다 (AC-040) |

| 종류·우선순위 선택 | 같은 방식으로 필터 (목록마다 하나 선택, `전체`가 조건 없음, 선택한 항목을 다시 눌러도 해제되지 않음) | AND 결합 (AC-027, AC-047) |
| `보드로 돌아가기` 또는 사이드바 `보드` | SCR-001로 이동 | 같은 결과 |

**상태별 화면**:

| 상태 | 표시 내용 |
|------|----------|
| 로딩 | 읽는 동안 열 머리만 보인다 (200ms 이내) |
| 빈값 (보관한 카드 0건) | 목록 자리에 `보관한 카드가 없습니다. 완료한 카드에서 보관을 누르면 이곳에 모입니다.` 오류 없이 열린다 |

## 결정 필요

> 사용자가 정하는 것이다. 각 항목에 지금 설계가 쓰는 임시 가정을 적었다. 1, 3번은 README의 미해결에 올릴 만하다. 4번은 해소됐다. 12번은 구현 단계에서 실제 창을 측정해 확정한다.

1. **칸 안 카드 순서 (CAND-005)**: 정렬 방식을 사용자가 말하지 않았다. 설계에 꼭 필요한 최소한으로 **임시 가정**: 보드는 만든 순서의 최신이 위, 보관함은 보관한 날 최신이 위. 마감 지난 카드를 위로 올리거나 정렬 버튼을 만들지 않았다. 선택지: (a) 이대로, (b) 마감일순, (c) 우선순위순, (d) 직접 끌어 정렬. 권고: 사용해 본 뒤 정한다.
2. **키보드만으로 조작 (CAND-010)**: 카드 만들기·상태 변경·저장을 키보드만으로 하는 것을 요구로 정할지 사용자가 말하지 않았다. 확정하지 않았다. 지금 설계는 네이티브 요소를 쓰므로 Tab 이동과 포커스 표시는 되고, 끌기의 대안으로 `⋯` 메뉴(보드)와 카드 입력 화면의 마감일 칸(캘린더)을 두었다. 전용 단축키와 보드 안 방향키 이동은 설계하지 않았다. 선택지: (a) 요구하지 않는다, (b) 요구로 올리고 단축키·방향키 이동을 설계한다. 권고: 사용자 확인 뒤 결정.
3. **보관 해제 (CAND-003)**: 만들지 않았다. 지금은 보관하면 보관함에서 보기와 삭제만 가능하다(ASM-015). 실수로 보관해도 보드로 되돌릴 수 없으므로 **임시 안전장치**로 보관 전에 `보관 확인` 한 단계를 둔다. 선택지: (a) 이대로, (b) 보관 해제를 요구로 올린다(그러면 확인 단계를 없앨 수 있다). 권고: 사용자 확인 뒤 결정.
4. **보관한 카드의 삭제 허용 여부**: 해소됨. 사용자가 보관한 카드도 보관함에서 삭제할 수 있다고 정했다(확인 단계 뒤 삭제, 진행 기록 함께 삭제. 명세 v3: UC-009 선행 조건 수정, AC-040). 수정과 기록 추가는 보관 카드에서 할 수 없다. 설계: 보관함 행의 `삭제`(인라인 확인)와 보기 전용 상세의 `삭제`.
5. **입력 중 닫기 경고 (CAND-006)**: 입력하다가 `취소`, ✕, Esc를 누르면 경고 없이 닫아 내용이 사라진다 (UC-001 Alt Flow 2를 따른 **임시 가정**). 선택지: (a) 이대로, (b) 입력이 있을 때 확인 한 단계. 권고: 사용자 확인 뒤 결정.
6. **캘린더의 완료·마감 지난 카드 표시 (CAND-007)**: **임시 가정**: 완료 카드는 흐린 제목 + 원 안 체크로 보이고, 마감 지난 카드는 붉은 칩. 선택지: 완료 카드를 캘린더에서 숨긴다 / 이대로. (v4에서 완료 카드도 끌 수 있다고 정해져(ASM-018) 완료 칩도 끌 수 있다)
7. **캘린더에 검색·필터 적용 여부**: 명세는 FR-013의 화면을 SCR-001, SCR-004로 한정했다. **임시 가정**: 캘린더는 항상 모든 카드를 보이고 사이드바 필터 영역을 숨긴다. 선택지: 캘린더에도 적용(명세에 SCR-003 추가 필요).
8. **오류 표시 색**: 붉은색(`overdue`)이 이미 `마감 지남`에 쓰이고 포인트는 조작·선택에만 쓰이므로, 오류에는 새 색을 쓰지 않고 아이콘과 문구와 굵은 테두리로 보인다. 오류에 붉은색을 같이 쓰면 마감 지남과 뜻이 섞인다. 선택지: (a) 이대로, (b) 오류 전용 색을 더한다(색 체계 변경, 사용자 재승인 필요). 권고: 이대로 쓰다가 필요하면 추가.
9. **종류·우선순위 필터의 선택 방식**: 해소됨(명세 v4). AC-047이 목록마다 `전체` 항목을 두고, 한 목록에서는 항목 하나만 선택하며, 선택된 항목을 다시 눌러도 해제되지 않는 방식으로 정했다. 두 목록은 AND다. 다중 선택은 없다.
10. **설계 가정 묶음(확인 선택)**: 최소 창 크기 1200x700, 캘린더는 월 보기가 기본이고 보기·기간은 저장하지 않음, 진행 기록에 붙는 상태는 저장된 카드 상태, 진행 기록은 오래된 것이 위, 보관은 완료 카드에서만 보이는 버튼. 사용자가 말하지 않은 값이라 취향과 다르면 알려 주면 된다. (v4에서 마감일 입력은 날짜 선택 칸으로 바뀌었다, AC-043)
11. **글꼴 라이선스 원문과 용량**: SUIT가 SIL OFL 1.1이라는 것은 저장소 README에서 확인했다. 라이선스 파일 원문과 woff2 실제 용량은 이 작업에서 열어 보거나 측정하지 못했다. 구현 전에 원문을 확인하고 라이선스 문구 파일을 글꼴과 함께 둔다. 외부 주소로 부르는 방식(저장소가 안내하는 CDN)은 NFR-001 때문에 쓰지 않는다.
12. **기본 창 높이 확정 (AC-048)**: **설계 기본값 920**(바깥 크기, 너비 1280 유지, 최소 1200x700 유지). 근거는 SCR-003의 `월 보기 높이 계산`: 안쪽 필요 834 + 창 틀 약 60(제목 표시줄·테두리 약 40, 기본 메뉴 막대 약 20, 이 PC에서 측정하지 못한 추정) = 약 894에 여유를 더한 값이다. 선택지: (a) 920(여유 약 26), (b) 900(여유 약 6), (c) 960(여유 약 66, 작업 영역 약 1040에서 열 수 있는 상한). 구현 단계에서 실제 창으로 안쪽 높이와 `+N`이 있는 5주 달의 격자 높이를 측정해 확정한다. 함께 확인할 것: (i) 1080p에서 화면 배율이 100%일 때 작업 영역이 약 1040이다. 배율 125%이면 작업 영역이 약 830(DIP)이라 920이 화면에 다 들어가지 않을 수 있다. 그때는 창 높이를 작업 영역에 맞춰 줄이면 캘린더가 안에서 스크롤된다. (ii) 창 틀 추정의 불확실성을 없애려면 `useContentSize`로 안쪽 크기(약 860)를 직접 지정하는 방법이 있다. (iii) 기본 메뉴 막대를 감출지는 사용자가 말하지 않았다. 권고: (a)로 시작해 측정으로 확정.
13. **마감일 칸에 입력하다 만 값 (AC-029)**: 날짜 선택 칸(`input type="date"`)은 일부만 채웠거나 없는 날짜를 입력하면 값을 내지 않고 빈 값이 되며, 브라우저가 잘못된 입력 상태(`validity.badInput`)로만 안다. 그대로 두면 사용자가 날짜를 입력한 줄 아는데 마감 없음으로 저장될 수 있다. **임시 가정**: 구현이 이 상태를 감지해 기존 오류 문구 `존재하지 않는 날짜입니다. 2026-11-06 형식으로 입력하세요`를 칸 아래에 보이고 저장하지 않는다. 선택지: (a) 이 가정, (b) 빈 값(마감 없음)으로 저장. 또 칸에 보이는 날짜 모양은 브라우저 로케일을 따르므로(한국어 `2026. 11. 06.` 꼴로 추정, 확인하지 못함) 문구의 `2026-11-06 형식` 예시가 칸의 모양과 다를 수 있다. 문구는 도메인 쪽이라 이 설계에서 바꾸지 않았다. 권고: (a).
14. **이 달 밖 칸에 놓은 칩 (AC-044)**: 명세대로 이전/다음 달에서 넘어온 칸에 놓아도 마감일이 그 날짜로 바뀐다. 그런데 이 칸은 지금 설계에서 카드를 그리지 않는 칸이라(`bg-side` 바탕, 카드 없음) 저장이 성공하면 칩이 이 달 보기에서 사라져 보이고 하단 줄 `N월에 마감인 카드 N건`만 줄어든다. 사용자가 카드가 사라졌다고 느낄 수 있다. **임시 가정**: 이대로 두고 이전/다음 달로 이동하면 보인다. 선택지: (a) 이대로, (b) 이 달 밖 칸에도 그 날짜의 칩을 보인다(캘린더 표시 규칙이 바뀌고 `+N`·월 경계 처리가 늘어난다), (c) 이 달 밖 칸은 놓을 수 없는 칸으로 한다(명세 AC-044/지시와 어긋나 명세 확인이 필요하다). 권고: (a)로 시작해 써 본 뒤 정한다.

| 같은 모양의 카드 반복 | 시선 위계를 화면마다 적었다. 마감 지남과 진행 중 칸이 1, 2순위다 |
| 큰 숫자 하나와 작은 통계 | 없다 |
| 흐림·유리 효과, 장식 격자, 그림자 | 없다. 달력 격자는 날짜 구획 기능이다. 대화상자 구분은 `scrim`과 1px 테두리다. 끌리는 칩의 투명도 50%는 상태 표시이고 흐림 효과가 아니다 |
| 모서리 | 4px, 3px, 오늘 표시 알약만 11px |
| 깜빡임, 자동 이동 | 없다. 움직임은 상태가 바뀔 때 150ms 이내 |
| 라벨 없는 입력 | 모든 입력에 항상 보이는 라벨. 검색 입력은 `검색` 라벨이 칸 안에 항상 있다 |
| 모든 필드 필수 | 필수는 제목 하나 |
| 제목 위 작은 라벨, 아이콘 타일 | 쓰지 않았다. 아이콘은 종류·마감 지남·완료를 뜻할 때만 타일 없이 쓴다 |
| 문구 | 명세 용어(개발 버그, 할 일, 진행 중, 완료, 보관, 마감 지남)와 예시 데이터. 구호, 막연한 약속, `Lorem ipsum` 없음 |

- **시안과 다르게 한 것과 사유**: (1) 사이드바 필터의 네모 체크 칸을 라디오 원으로 바꿨다. 한 목록에서 하나만 고르는 방식이 명세(AC-047)로 확정됐다. (2) 카드 오른쪽 위에 `⋯` 버튼을 더했다. 끌기만 있으면 끌지 않는 대안이 없어서다(WCAG 2.5.7). (3) 카드 보조 정보와 사이드바 글자를 13에서 14로 올렸다. (4) 사이드바에 화면 밝기 묶음을 더했다(FR-014). (5) 색 체계를 사용자 요청으로 따뜻한 색(포인트 테라코타, 칸별 색, 붉은 마감 지남)으로 바꿨다. 시안 V-A 원 색(무채색 + 앰버)과 다르다. (6) 시안 SCR-001 하단의 `... 글자와 아이콘으로도 구분됩니다` 설명 문장은 화면이 스스로를 설명하는 문구라 뺐다
