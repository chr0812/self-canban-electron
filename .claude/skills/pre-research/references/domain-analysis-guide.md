# Domain Analysis Guide

도메인 분석 수행 절차와 출력 형식을 정의한다.

## 수행 절차

### 1. 도메인 식별

주제에서 핵심 도메인 키워드 추출:
- 주 도메인 (1개)
- 관련/인접 도메인 (1~3개)
- 도메인 분류 (B2C/B2B/B2G, 산업군)

### 2. 핵심 용어 정의 (5~10개)

해당 도메인에서 반드시 알아야 하는 용어:
- 용어명 (영문 병기)
- 정의 (1~2줄)
- 이 프로젝트에서의 의미

### 3. 비즈니스 규칙

도메인 고유의 규칙:
- 계산 공식 (가격, 수수료, 포인트 등)
- 검증 규칙 (유효 범위, 형식)
- 정책 (환불, 차단, 탈퇴 등)
- 워크플로우 규칙 (승인 절차, 상태 전이)

### 4. 규제 / 법적 요건

- 개인정보보호법 (GDPR, 한국 개인정보보호법)
- 산업별 규제 (금융: 전자금융거래법, 의료: 의료법, 식품: 식품위생법)
- 연령 제한, 인증 요건
- 해당 없으면 "특수 규제 없음" 명시

### 5. 비즈니스 모델

해당 도메인의 일반적 수익 모델:
- 구독, 광고, 수수료, 프리미엄, 라이선스 등
- 이 프로젝트에 적합한 모델 후보

### 6. 데이터 규모 추정

설계자가 DB/캐싱/인프라 결정 시 참고:
- 사용자당 / 일: 핵심 엔티티 일일 생성량
- 사용자당 / 1년: 누적 추정
- 시스템 전체 / 1년: DAU 목표 기반
- 보존 정책: 영구 / N일 / 탈퇴 시 삭제

> 정밀 수치보다 자릿수(order of magnitude)가 중요.

## WebSearch 키워드 패턴

```
"{도메인} 핵심 개념"
"{도메인} 비즈니스 규칙"
"{도메인} 규제 한국 {현재연도}"
"{도메인} 비즈니스 모델"
"{도메인} 데이터 규모"
```

## 출력 형식

```markdown
# Domain Analysis: {도메인명}

> 조사일: {YYYY-MM-DD}

## 도메인 식별
- 주 도메인: {도메인}
- 관련 도메인: {목록}
- 분류: {B2C/B2B 등}

## 핵심 용어
| # | 용어 | 영문 | 정의 | 프로젝트 맥락 |
|---|------|------|------|--------------|

## 비즈니스 규칙
- {규칙 1}: {설명}
- {규칙 2}: {설명}

## 규제 / 법적 요건
- {규제 1}: {적용 범위} | 출처: {URL or [일반 지식 폴백]}
- (해당 없으면 "특수 규제 없음" 명시)

## 비즈니스 모델
| 모델 | 설명 | 이 프로젝트 적합도 |
|------|------|-------------------|

## 데이터 규모 추정
| 항목 | 추정치 | 근거 |
|------|--------|------|
| 사용자당/일 | {N} | {근거} |
| 사용자당/1년 | {N} | 누적 |
| 시스템 전체/1년 | {N} | DAU {M} 기준 |

설계 영향 메모:
- {DB 선택, 캐싱, 샤딩 관련 시사점}
```

## 규칙

- 결론 위주 작성, 원문 복사 금지
- 모든 항목에 출처 명시 (URL 또는 [일반 지식 폴백])
- 데이터 규모는 자릿수 단위로 충분
- 규제 섹션은 "없음"도 명시적으로 기술
