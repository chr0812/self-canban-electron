# AI 티 규칙 (Anti-slop)

화면 설계가 "AI가 반사적으로 만든 것"처럼 보이지 않게 하는 금지 목록이다. **처방이 아니다.** 무엇을 할지는 시안의 방향(`directions.md`)이 정하고, 이 문서는 무엇을 하지 않을지만 정한다.

> 분류와 사례 이름은 Impeccable(Paul Bakaus 작, Apache-2.0)의 공개 카탈로그(`impeccable.style/slop`, 2026-10-30 확인)를 참고했다. 문구는 직접 썼고 앱 설계 단계에 맞게 골랐다. 카탈로그에는 랜딩 페이지용 항목과 코드 오류 항목이 많아 앱 설계에 해당하는 것만 담았다.
> 카탈로그 전체 규칙을 코드로 검사하는 도구(`npx impeccable detect`)는 구현 단계의 선택 명령으로만 쓴다. 이 하네스는 그 도구를 실행하지 않고, 아래 규칙의 일부만 게이트가 본다.

## 누가 어떻게 쓰는가

| 누가 | 어떻게 |
|------|--------|
| `design-ui-direction`, `design-ui` | 시안과 화면 설계를 쓰기 전에 읽는다. 걸리는 항목은 쓰지 않는다. 도메인이 요구해서 쓰는 것은 근거를 적는다 |
| 리뷰어 | 설계 산출물이 규칙에 걸리는지 본다 |
| 게이트 | 기본값 글꼴(`DSN-03`), 디자인 토큰 표(`DSN-04`), 시선 위계(`DSN-05`)만 본다. 나머지는 사람이 본다 |
| 구현 단계(선택) | `npx impeccable detect`를 `01-tech-stack.md` 명령 표의 `lint:design`으로 둘 수 있다. 코드와 렌더된 화면이 대상이라 SVG 와이어프레임에는 적용되지 않는다 |

규칙에 걸려도 **도메인이 요구하면 쓸 수 있다.** 단 사유를 `04-ui-spec.md` 해당 화면에 한 줄로 적는다("러닝 직후 한눈에 보이는 큰 숫자가 핵심 가치라서 큰 숫자 + 보조 통계 배치를 쓴다"). 사유 없이 반사적으로 쓰는 것이 문제다.

## 기본값 글꼴

디자인 토큰의 글꼴이 아래에 있으면 `DSN-03` 경고다. 쓰려면 토큰 표의 같은 줄에 `[사용자 입력]`과 사유(브랜드 지정 등)를 적는다. 이 목록은 게이트 코드(`scripts/lib/stages/design-direction.js`의 `OVERUSED_FONTS`)와 같아야 하고, 테스트가 둘의 일치를 확인한다.

- `Inter` — Impeccable 카탈로그가 이름을 든다
- `Geist` — Impeccable 카탈로그가 이름을 든다
- `Arial` — 이 하네스가 더한 범용 기본값
- `system-ui` — 이 하네스가 더한 시스템 기본 글꼴
- `-apple-system` — 이 하네스가 더한 시스템 기본 글꼴
- `BlinkMacSystemFont` — 이 하네스가 더한 시스템 기본 글꼴
- `시스템 기본` — 이 하네스가 더한 표기

기본값 글꼴을 피하라는 것이지 특정 글꼴이 나쁘다는 뜻이 아니다. 시안의 글자 축(세리프 중심 / 산세리프 기하형 / …)에 맞는 글꼴을 고르고, 한글 글꼴은 화면 크기에서 읽히는지(획 굵기, 자간)를 본다.

## 규칙

범례: **설계** = 설계 산출물(UI 명세, SVG)에서 점검, **구현** = 코드에서 점검(선택 명령). 괄호는 참고한 카탈로그 항목 이름.

### 타이포

| 하지 않는다 | 대신 | 단계 |
|-------------|------|------|
| 기본값 글꼴을 이유 없이 쓴다 (Just another Inter headline) | 시안의 글자 축에 맞는 글꼴. 위 목록 참고 | 설계 |
| 크기·굵기·간격이 비슷해 제목과 본문이 구분되지 않는다 (Flat type hierarchy) | 글자 크기 단계를 토큰으로 정하고 단계 사이를 눈에 띄게 벌린다 | 설계 |
| 제목과 본문이 같은 글꼴·굵기다 (Heading in the body font) | 제목에 굵기나 글꼴을 달리한다 | 설계 |
| 큰 기울임 세리프 제목으로 "에디토리얼 느낌"을 낸다 (Beautifully Crafted) | 세리프를 쓰더라도 구성과 여백으로 편집 느낌을 낸다 | 설계 |
| 모든 제목 위에 작은 라벨이나 알약 배지를 붙인다 (Features, Introducing) | 라벨이 정보를 더할 때만 쓴다 | 설계 |
| 제목마다 둥근 사각형 안 아이콘을 위에 얹는다 (Icon tile stacked above heading) | 아이콘이 의미를 줄 때만, 타일 없이 | 설계 |
| 조작 요소·내비게이션 글자가 너무 작다 (Tiny interface text) | 본문 14px 이상, 조작 요소 12px 이상을 기본으로 한다 (이 하네스의 기준) | 설계 |
| 긴 본문을 모두 대문자로, 또는 자간을 과하게 벌린다 (All-caps body text, Wide letter spacing) | 대문자·넓은 자간은 짧은 라벨에만 | 설계 |
| 한 줄이 너무 길다 (Line length too long) | 본문 한 줄은 대략 45~75자 안팎 | 구현 |

### 색

| 하지 않는다 | 대신 | 단계 |
|-------------|------|------|
| 보라-파랑 그라데이션, 어두운 배경 위 밝은 청록 (AI color palette) | 시안의 색 논리 축에서 고른 팔레트 | 설계 |
| 어두운 배경에 네온 테두리와 글로 (Neon on dark, Ambient glow, A soft spotlight) | 강조는 색 한두 개와 대비로 | 설계 |
| 크림·베이지를 고민 없이 기본으로 쓴다 (The tasteful default) | 팔레트를 고른 이유를 토큰 표 비고에 적는다 | 설계 |
| 색 배경 위에 회색 글자를 쓴다 (Gray text on colored background) | 배경 색에 맞춘 글자 색 | 설계·구현 |
| 글자 대비가 모자란다 (Low-contrast text) | 본문 4.5:1 이상 (WCAG AA). 토큰 표에 대비를 적는다 | 설계·구현 |

### 레이아웃과 공간

| 하지 않는다 | 대신 | 단계 |
|-------------|------|------|
| 카드 안에 카드를 넣는다 (Nested cards) | 구획은 여백과 구분선으로, 카드는 한 겹만 | 설계 |
| 같은 모양의 카드를 줄줄이 반복해 모든 항목이 같은 비중이다 (Feature repeated, Monotonous spacing) | 화면마다 **시선 위계**를 쓰고 1순위를 크게 둔다 (`DSN-05`) | 설계 |
| 의미 없는 순서 번호를 제목 옆에 붙인다 (Tiny numbered section labels) | 순서가 있을 때만 | 설계 |
| 큰 숫자 하나와 작은 보조 통계를 습관적으로 쓴다 (Hero metric layout) | 핵심 가치가 그 숫자일 때만 쓰고 사유를 적는다 (예: 러닝 기록) | 설계 |
| 카드 한쪽에 두꺼운 색 띠를 붙여 알림처럼 보이게 한다 (Alert title, Border accent on rounded element) | 상태 표시는 아이콘과 문구로 | 설계 |
| 흐림·유리 효과를 장식으로 쓴다 (Frosted glass card) | 겹침을 구분해야 할 때만 | 설계 |
| 모서리를 지나치게 둥글게 한다 (44px radius) | 토큰의 모서리 값을 정해 일관되게 | 설계 |
| 가로줄·격자 무늬로 빈 곳을 채운다 (Decorative grid-line background) | 빈 곳은 비워 둔다 | 설계 |
| 요소가 컨테이너를 넘치거나 팝업이 잘린다 (Content overflowing, Clipped menus) | 화면 크기별 레이아웃을 점검한다 | 구현 |

### 모션

| 하지 않는다 | 대신 | 단계 |
|-------------|------|------|
| 상태가 바뀌지 않았는데 점이 계속 깜빡인다 (Systems operational) | 상태가 바뀔 때만 알린다 | 설계 |
| 정적인 글 옆에 깜빡이는 커서를 둔다 (Decorative blinking cursor) | 편집 가능한 곳에만 커서 | 설계 |
| 로고·문구가 자동으로 흐른다 (Auto-scrolling marquee) | 정지·멈춤 수단이 없는 자동 이동은 쓰지 않는다 | 설계 |
| 평범한 확인 창이 튀거나 출렁인다 (Confirm action) | 시안의 움직임 축 값을 따른다. 기본은 짧은 전환 | 설계 |

### 문구(카피)

| 하지 않는다 | 대신 | 단계 |
|-------------|------|------|
| "업무 효율을 극대화" 같은 막연한 약속 (Supercharge your workflow) | 사용자가 하는 행동을 구체적인 동사로 | 설계 |
| 모든 항목을 "A가 아니라 B" 구호 문장으로 쓴다 (Not a feature. A platform.) | 사실과 행동을 담담히 | 설계 |
| 줄표(—)를 거의 모든 문장에 쓴다 (Em-dash overuse) | 문장을 나누거나 쉼표 | 설계 |
| 한 컨테이너 안에 같은 라벨이 여러 번 나온다 (Ready repeated) | 자리마다 다른 정보를 쓴다 | 설계 |

화면 문구 예시는 명세의 용어와 실제 예시 데이터로 쓴다. "Lorem ipsum"이나 "항목 1"을 시안에 두지 않는다.

### 폼

| 하지 않는다 | 대신 | 단계 |
|-------------|------|------|
| 라벨 없이 placeholder만 둔다 | 라벨을 항상 보이게 | 설계·구현 |
| 모든 필드를 필수로 한다 | 꼭 필요한 것만 필수, 나머지는 나중에 | 설계 |
| 한 화면에 필드가 너무 많다 | 단계를 나누거나 줄인다 | 설계 |

### 구조와 이미지

| 하지 않는다 | 대신 | 단계 |
|-------------|------|------|
| 제목 단계를 건너뛴다 (Skipped heading level) | h1 → h2 → h3 순서 | 구현 |
| 자리표시 느낌의 원·사각형 일러스트를 그대로 쓴다 (Placeholder-style illustrations) | 일러스트는 방향이 정할 때만, 정하면 제대로 | 설계 |
| 이미지 위를 거의 불투명한 막으로 덮는다 (94% wash) | 글자 가독성은 이미지 영역을 나눠서 | 설계 |

## 이 규칙의 한계

- 이 목록은 외부 카탈로그를 설계 단계에 맞게 줄인 것이다. 카탈로그 전체(67개 안팎)는 도구가 코드를 검사할 때 쓴다.
- 규칙을 모두 지켜도 **좋은 디자인**이 되는 것은 아니다. 금지 목록은 반사적인 선택을 줄일 뿐이고, 좋은 선택은 시안의 방향과 사용자가 정한다.
- 이 규칙을 지키려고 모든 화면이 또 다른 "획일적인 모양"(예: 모든 화면이 에디토리얼)이 되면 실패다. 그래서 시안은 서로 다른 방향이어야 한다 (`directions.md`).
