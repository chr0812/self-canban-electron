# 07-test-plan.md 템플릿

시험 설계자(`design-test`)가 쓰는 형식. 명세의 인수 기준(AC)을 시험 시나리오(TC)로 펼친다.
게이트가 읽는 것: `### TC-NNN` 헤딩, `- 근거:`의 ID, `- 실행:` 값. 나머지 필드는 사람과 개발자가 읽는다.

```markdown
# 시험 계획

> 작성일: {YYYY-MM-DD}
> 입력: docs/04-spec/spec.md 인수 기준·UC·NFR·도메인 규칙 + 설계 산출물

## 시험 전략

- 단위: {무엇을, 어떤 도구로 — 01-tech-stack 의 명령 표 용도 이름}
- 통합: {…}
- E2E: {…}
- 수동: {사람이 확인하는 것과 이유}
- 시험 데이터: {원칙. 실제 개인정보를 쓰지 않는다 등}

## 시험 시나리오

### TC-001 {제목}
- 근거: AC-001, UC-001
- 수준: 단위
- 실행: cli
- 전제: {시작 상태}
- 절차: {무엇을 한다}
- 입력: {시험 데이터}
- 기대 결과: {관찰할 수 있는 결과}

### TC-002 {제목}
- 근거: AC-004
- 수준: E2E
- 실행: manual
- 수동 사유: {자동화하지 않는 근거와 대상 브라우저·기기}
…

## 추적 요약

| 근거 | TC |
|------|----|
| AC-001 | TC-001 |
| NFR-001 | TC-007 (manual) |

## 결정 필요

## 검증 기록
```

- `실행`: `cli`(명령줄, 화면 없음) / `browser`(헤드리스 브라우저 E2E) / `device`(에뮬레이터·실기기) / `manual`(사람 판단).
- `manual` TC 는 `- 수동 사유:` 필수 — 자동화하지 않는 근거와 대상 브라우저·기기 (`VAL-14`). 측정할 수 있는 부분은 자동 TC 로 나눈다.
- TC 를 지우면 번호를 다시 쓰지 않고, 문서 끝 `## 변경 이력` 표(`| 판 | 날짜 | 내용 | 삭제 ID |`)의 `삭제 ID`에 적는다. 그 열의 ID 는 결번·정의 없는 ID 검사에서 빠진다.
- `cli`·`browser`·`device`는 `01-tech-stack.md`의 `시험 환경` 표에 같은 실행 위치 행이 있어야 한다 (`VAL-14`).
- 모든 AC는 하나 이상의 TC 근거에 있어야 한다 (`REF-09`). NFR이 빠지면 경고 (`REF-11`).
- 자동 TC(`manual` 아닌 것)는 `08-tasks.md`의 어떤 Task의 `check:`에 있어야 한다 (`REF-10`). 테스트 코드는 그 Task에서 함께 쓴다.
- 추적 요약 표는 사람이 보기 위한 것이다. 게이트는 시나리오의 `근거`로 직접 계산한다.
